讲解说「有 GetAwaiter 就能 await」，但 FVoid 里没有这个方法，为什么它也能被 await？

2026-07-28 · 相关：Fantasy.Unity/Runtime/Core/FTask/Task/FVoid.cs

线索

  • 「鸭子类型 awaitable 契约」和「awaiter 形态」是两条不同的路
  • FVoid 自己就是 awaiter，不是 awaitable

核心理解

C# 让一个类型可被 await 有两条路径。讲解里说的「有 GetAwaiter() 就能 await」描述的是 通用 awaitable 契约（鸭子类型：提供 GetAwaiter() 返回一个具备 IsCompleted/OnCompleted/GetResult 的 awaiter）。 FTask、Task、UniTask 都走这条。

FVoid 走的是另一条：它自己直接实现 awaiter 接口（ICriticalNotifyCompletion）， 自己当 awaiter，省掉了 GetAwaiter() 这一跳。它只在 async FVoid 方法的编译器状态机内部使用， 配合 [AsyncMethodBuilder] 由编译器直接调用它的 IsCompleted/UnsafeOnCompleted， 所以根本不需要 GetAwaiter。

证据

FVoid.cs —— 整个类型没有 GetAwaiter()，直接把 awaiter 三件套长在自己身上

[AsyncMethodBuilder(typeof(AsyncFVoidMethodBuilder))]
internal struct FVoid : ICriticalNotifyCompletion
{
    public bool IsCompleted => true;          // 恒完成，永不挂起
    public void OnCompleted(Action continuation) { }
    public void UnsafeOnCompleted(Action continuation) { }
}

引用：Fantasy.Unity/Runtime/Core/FTask/Task/FVoid.cs:8-28。注意 FVoid 连 GetResult() 都没有，只有个空的 Coroutine()——因为 IsCompleted 恒为 true，编译器走快速路径直接跳过 GetResult。

关键区分 讲解那句「有 GetAwaiter 就能 await」没错，但它讲的是通用规则。FVoid 是特例：awaitable 与 awaiter 合一、只服务于 async FVoid 的零开销 fire-and-forget。看到没有 GetAwaiter 却能 await 的类型，先查它是不是直接实现了 INotifyCompletion/ICriticalNotifyCompletion。

AsyncMethodBuilder 到底是什么？为什么 FVoid、FTask 上都要贴这个特性？

2026-07-28 · 相关：Fantasy.Unity/Runtime/Core/FTask/Builder/AsyncFVoidMethodBuilder.cs

线索

  • async 关键字 = 编译时把方法切成状态机的语法糖
  • 编译器不认识你造的类型，Builder 就是状态机和你类型之间的「胶水层」
  • 7 个固定签名方法的契约

核心理解

AsyncMethodBuilder 是编译器的脚手架。async 关键字在 C# 里不是运行时魔法，是编译时把方法体改写成 IAsyncStateMachine 状态机的语法糖。但编译器只认识 System.Threading.Tasks.Task， 碰到第三方自己造的 FTask/FVoid/UniTask，它不知道「怎么创建这个 task、完成时怎么收尾、异常往哪抛」。

所以 C# 提供了一个约定：你在类型上贴 [AsyncMethodBuilder(typeof(XxxBuilder))]， 指向一个实现了 7 个固定签名方法的「建造者」，由它负责在状态机的每个关键节点跟你的类型打交道。 Builder = 状态机和自定义 Task 类型之间的胶水层。

证据 —— Builder 的 7 个固定方法，对应状态机的 7 个调用点

AsyncFVoidMethodBuilder.cs —— 最简 builder，struct 零字段全 inline

internal struct AsyncFVoidMethodBuilder
{
    public FVoid Task => default;                       // 读 Task 属性：返回最终对象
    public static AsyncFVoidMethodBuilder Create() => default;  // 进 async 方法时调用
    public void Start<TSM>(ref TSM sm) where TSM : IAsyncStateMachine
        => sm.MoveNext();                              // 启动状态机，同步跑第一片段
    public void SetResult() { }                      // 方法正常 return 完
    public void SetException(Exception ex)                 // 方法体抛异常
        => ExceptionDispatchInfo.Capture(ex).Throw();
    public void AwaitOnCompleted<...>(...)             // 挂起：登记续体（普通版）
        => awaiter.OnCompleted(sm.MoveNext);
    public void AwaitUnsafeOnCompleted<...>(...)         // 挂起：登记续体（跳过上下文版）
        => awaiter.UnsafeOnCompleted(sm.MoveNext);
}

引用：Fantasy.Unity/Runtime/Core/FTask/Builder/AsyncFVoidMethodBuilder.cs:11-61

对照：编译器把 async 方法翻成了什么

// 你写的：
async FVoid Foo() { await Bar(); }

// 编译器翻译成（伪代码）：
FVoid Foo() {
    var sm = new FooStateMachine();
    sm.builder = AsyncFVoidMethodBuilder.Create();   // ← Create()
    sm.builder.Start(ref sm);                     // ← Start()，跑到第一个 await
    return sm.builder.Task;                      // ← Task 属性
}
void MoveNext() {
    // ...await 一个未完成 task...
    builder.AwaitUnsafeOnCompleted(ref awaiter, ref this);  // ← 登记续体
    return;
    // ...被唤醒跑完...
    builder.SetResult();      // ← 或 SetException(ex)
}
FVoid 的 Builder 为什么这么空 Create()/Task 都 return default（struct 零值就够，不分配），SetResult() 空实现（fire-and-forget，完成了不用通知任何人），Start() 同步调一次 MoveNext。整个 builder 是 struct、零字段、全 [AggressiveInlining]，编译器内联后 async FVoid 几乎零开销——这正是 Fantasy 要为 fire-and-forget 单独造 FVoid 而不用 FTask 的原因。
造自己的 awaitable 类型，两样都不能少 除了实现 awaiter 契约（IsCompleted/OnCompleted/GetResult），还必须配一个 Builder 并在类型上贴 [AsyncMethodBuilder(typeof(...))]。缺任何一个，async YourType 都编译不过。
