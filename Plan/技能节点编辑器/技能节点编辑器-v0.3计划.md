# 运行时技能执行引擎 v0.3 开发计划

## Context

技能图编辑器（v0.2）已完整实现。v0.3 的唯一目标是：**跑通最小执行链路**，验证：

`Entry -> Debug("开始") -> Delay(1s) -> Debug("结束")`

按顺序执行，且中间延时正确。

本轮是纯 MVP，不追求通用技能系统，不提前实现服务端、预测回滚、Blackboard、复杂分支。

**网络架构背景**：服务端权威 + 客户端预测回滚，但 v0.3 只验证客户端本地执行闭环。

**关键约束**：
- `GameShared` 通过链接文件被服务端 `Entity.csproj` 自动编译
- 执行器核心代码放在 `GameShared`，不直接依赖 `TEngine/UnityEngine`
- 异步统一使用 `FTask`
- 运行时 JSON 反序列化不能使用 `JsonUtility`
- 本轮只支持 `Entry` / `Debug` / `Delay` 三种运行时节点

---

## MVP 边界

### 本轮只支持

- 单条顺序执行链
- 1 个 `Entry`
- `Debug.message`
- `Delay.duration`
- 从编辑器导出 JSON 后在客户端加载并执行

### 本轮不支持

- `Action` / `Condition` 运行时处理器
- 多分支选择
- 服务端处理器
- 客户端预测 / 回滚
- Blackboard 共享变量
- 更多 MOBA 专用节点

---

## 运行时 JSON 契约

先固定运行时数据结构，再做导出器和执行器，避免后期返工。

```json
{
  "skillName": "TestSkill",
  "nodes": [
    { "nodeId": 0, "nodeType": "Entry", "properties": [] },
    { "nodeId": 1, "nodeType": "Debug", "properties": [{ "key": "message", "value": "开始" }] },
    { "nodeId": 2, "nodeType": "Delay", "properties": [{ "key": "duration", "value": "1" }] },
    { "nodeId": 3, "nodeType": "Debug", "properties": [{ "key": "message", "value": "结束" }] }
  ],
  "connections": [
    { "fromNodeId": 0, "fromPort": "Next", "toNodeId": 1 },
    { "fromNodeId": 1, "fromPort": "Out", "toNodeId": 2 },
    { "fromNodeId": 2, "fromPort": "Out", "toNodeId": 3 }
  ]
}
```

**导出约束**：
- 导出运行时只保留 `nodeType`、`properties`、`connections`
- 不导出 `position`
- 不导出 `title`
- `Debug` 节点运行时只依赖 `message` 属性，不依赖编辑器标题

## 实现步骤

### Phase 0：前置决策

先确定 2 件事：

1. **运行时 JSON 方案**
   - 不能使用项目默认 `Utility.Json` 的 `JsonUtility` 实现
   - 需要明确一个可用于客户端和服务端的 JSON 反序列化方案

2. **运行时服务抽象**
   - `GameShared` 不直接打印 Unity 日志
   - `GameShared` 不直接调用 Unity 计时器
   - 通过接口由客户端注入日志和延时能力

---

### Phase 1：运行时数据模型

**RuntimeSkillGraph.cs**

包含 4 个类型：
- `RuntimeSkillGraph`
- `RuntimeSkillNode`
- `RuntimeConnection`
- `RuntimeProperty`

最小能力：
- `FindEntryNode()`
- `GetNextConnections(nodeId, fromPort)`
- `GetPropertyValue(key)`
- `GetFloatPropertyValue(key, fallbackValue)`

目标：
- 只服务于当前 MVP
- 不做多余抽象

---

### Phase 2：执行器最小闭环

**SkillGraphRunner.cs**

包含：
- `ISkillNodeHandler`：`Execute(node, context) -> FTask<SkillExecuteResult>`
- `SkillExecuteResult`：`NextPort` + `Completed`
- `SkillNodeHandlerRegistry`
- `SkillGraphRunner`

`SkillGraphRunner.Run()` 逻辑：
- 从 `Entry` 开始
- 查找节点对应处理器
- 执行处理器
- 根据 `NextPort` 找下一条连线
- 顺序执行直到没有后继节点或执行结束

本轮只考虑单链顺序执行，不做复杂调度。

---

### Phase 3：执行上下文与运行时服务

**SkillContext.cs**

保留基础字段：
- `CasterId: long`
- `TargetId: long`
- `SkillId: int`
- `IsCancelled: bool`

新增运行时能力引用：
- `ISkillRuntimeServices Runtime`
- `FCancellationToken CancellationToken`

**ISkillRuntimeServices** 最小接口：
- `void Log(string message)`
- `FTask<bool> DelayAsync(int milliseconds, FCancellationToken cancellationToken = null)`

目的：
- 保持 `GameShared` 平台无关
- 把日志和等待交给客户端实现

---

### Phase 4：内置 Handler

**SkillHandlers.cs**

只实现 3 个处理器：

- `EntryNodeHandler`
  - 直接返回 `NextPort = "Next"`

- `DebugNodeHandler`
  - 读取 `message`
  - 调用 `context.Runtime.Log(message)`
  - 返回 `NextPort = "Out"`

- `DelayNodeHandler`
  - 读取 `duration`
  - 转换为毫秒
  - 调用 `await context.Runtime.DelayAsync(...)`
  - 返回 `NextPort = "Out"`

注意：
- `DebugNodeHandler` 不打印节点 `title`
- 运行时调试输出只依赖导出的属性

---

### Phase 5：编辑器 DebugNode

**DebugNode.cs**

- 继承 `SkillGraphNode`
- 1 个输入端口 `"In"`
- 1 个输出端口 `"Out"`
- 1 个属性：`message(string)`

同时修改：
- `SkillNodeType` 增加 `Debug`
- `SkillGraphNodeFactory` 增加 `Debug` 分支
- `SkillGraphSearchWindow` 增加 `Debug` 选项

---

### Phase 6：编辑器导出

**SkillGraphExporter.cs**

职责：
- 读取编辑器 `SkillGraphData`
- 分配 `int nodeId`
- 建立 `guid -> nodeId` 映射
- 把 `edges` 转为运行时 `connections`
- 导出到 `Assets/AssetRaw/Configs/SkillGraphs/`

导出时丢弃：
- `position`
- `title`
- 所有仅编辑器使用的字段

最小校验：
- 必须且只能有 1 个 `Entry`
- 边引用的节点必须存在
- `Debug.message` 不能为空
- `Delay.duration` 必须可解析

**SkillGraphEditor.cs**

- Toolbar 增加 `Export` 按钮

---

### Phase 7：客户端集成

**SkillExecutor.cs**

职责：
- `Singleton<SkillExecutor>`
- `OnInit()` 注册 `Entry / Debug / Delay` 处理器
- 加载技能图 JSON
- 反序列化为 `RuntimeSkillGraph`
- 构造 `SkillContext`
- 注入客户端 `ISkillRuntimeServices` 实现
- 创建 `SkillGraphRunner`
- 执行技能

接口建议：
- `CastSkill(string skillName, SkillContext context): FTask`

说明：
- 不使用 `UniTaskVoid` 作为核心执行接口
- 如果上层需要 fire-and-forget，由调用方自行 `.Forget()`

---

## 验证方式

1. 在编辑器中创建：
   `Entry -> Debug("开始") -> Delay(1s) -> Debug("结束")`
2. 点击 `Export`，确认导出 JSON 格式符合约定
3. 运行时调用 `CastSkill(...)`
4. 日志按顺序输出：
   - `"开始"`
   - 约 1 秒后
   - `"结束"`
5. `GameShared` 新增代码在客户端和服务端都编译通过

---

## 完成标准

达到以下条件即视为 v0.3 完成：

- 编辑器可创建并保存 `Debug` 节点
- 图可成功导出为运行时 JSON
- 客户端可加载并执行该 JSON
- `Entry -> Debug -> Delay -> Debug` 链路可稳定跑通
- `GameShared` 代码可被服务端项目编译
