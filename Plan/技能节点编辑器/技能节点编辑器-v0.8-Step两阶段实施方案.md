# 技能节点编辑器 v0.8（人话版）两阶段方案

## 这份计划到底在做什么

一句话：  
把技能图从“点一下就一口气跑完”，改成“每帧推进一点、能存档、能回档、能重放”。

这样做的目的不是炫技，而是为了后面的帧同步、回滚和线上问题排查。

---

## 现在的问题（为什么要改）

目前运行方式更像“黑盒一次跑完”，有几个痛点：

1. 变量初始值不够可控，开局状态容易不一致。  
2. 部分节点依赖真实时间和异步资源，天然不利于同步。  
3. 没有标准的“执行快照”，断线恢复和回滚困难。  
4. 没有统一“执行流水记录”，出错时不好比对哪一帧开始偏了。

---

## 两阶段怎么做

## 第一步（Step A）：先把内核跑通

目标：先把“能逐帧、能快照、能恢复”这套基础能力搭起来。

会做的事：

1. 运行时数据升级到 `0.8`。  
2. 导出时把变量定义和默认值带上，并做基础合法性检查。  
3. Runner 支持新接口：
   - `Initialize`（开始执行）
   - `Step`（推进一帧）
   - `GetSnapshot`（保存当前状态）
   - `Restore`（从快照恢复）
4. `Delay` 改成按帧推进，不再直接依赖真实毫秒。  
5. 在锁步模式下，`Action` 只发命令事件，不直接驱动资源结果。  
6. 记录最基础的执行事件流（进入节点、离开节点、分支、变量写入、命令发出、执行结束）。  
7. 保留旧的 `Run` 入口，避免现有调用全炸。

第一步不做的事：

1. 联网协议和完整同步框架。  
2. 快照压缩优化。  
3. 完整可视化调试工具。  
4. 预测误差校正。

第一步完成标准（满足这些就算过）：

1. 相同输入重复执行，结果和事件流一致。  
2. N 帧保存快照，恢复后继续跑，结果一致。  
3. 老的 `Run` 还能用。  
4. 导出阶段能拦住明显非法配置。

---

## 第二步（Step B）：把”能跑”变成”能上线”

目标：把测试覆盖、导出安全和排查能力补齐。

会做的事：

**B1（测试补齐，最高优先级）：**

1. 补 `Snapshot/Restore` 专项测试：
   - 第 N 帧快照，恢复后继续执行，验证结果一致
   - 带 `Delay` 节点的快照恢复（验证帧计数器正确恢复）
   - 带 `SetVariable` 的快照恢复（验证黑板状态正确）
   - 多次快照恢复的嵌套场景
2. 补确定性重放验证：同一个图跑两遍，自动比对事件流是否完全一致。
3. 补回滚一致性测试矩阵（多帧、多轮回滚重放）。

**B2（导出安全 + 编辑器体验）：**

4. 把 Lockstep 模式下导出校验规则补完整（静态检查，而非运行时拦截）。
5. 在编辑器里把同步风险提示做得更清楚，方便策划和程序提前发现问题。
6. 做事件流比对工具，能定位到”第几帧、哪个节点、哪个字段”不一致（基于第2条的确定性验证扩展）。

不做的事：

- 快照版本管理/兼容升级 → 等需要序列化落盘或网络传输时再做
- 快照体积压缩 → 当前黑板体积不构成问题，推迟

第二步完成标准：

1. `Snapshot/Restore` 有完整测试覆盖，回滚重放稳定一致。
2. Lockstep 模式下不安全配置能被导出阶段稳定拦截。
3. 事件流比对工具能定位到具体帧和节点。

---

## 对排期最有帮助的里程碑

1. A1：数据版本升级 + 变量导出校验 + Blackboard 初始化。
2. A2：Runner 支持 `Initialize/Step/Snapshot/Restore`。
3. A3：`Delay/Action` 适配 + 基础事件流 + 核心测试。
4. B1：Snapshot/Restore 专项测试 + 确定性重放验证 + 回滚测试矩阵。
5. B2：Lockstep 导出校验补齐 + 编辑器提示完善 + 事件流比对工具。

---

## 最后一句

Step A 解决“能不能做”；Step B 解决“敢不敢上线”。
