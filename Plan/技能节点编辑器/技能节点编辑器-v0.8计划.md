# 技能节点编辑器 v0.8 开发计划

## Context

`v0.7.1` 已完成编辑器可用性补齐：

- Delete 删除一致性
- Undo / Redo 快照时间线
- Blackboard 面板与变量联动
- MiniMap 导航

`v0.6` 也已完成运行时基础执行语义：

- `Success / Failure / Cancelled / Running`
- 分支与条件执行
- 基础异步节点（Delay / Action）

当前主矛盾已经从“图能不能编辑、能不能执行”，转为“能不能用于状态帧同步与回放”。

版本线说明：`技能节点编辑器 v0.8` 是子系统版本号，不等同于 `状态帧同步 v0.8`。  
本版本的 Step 内核交付目标是作为状态帧同步 `v0.5` 的前置能力。

从现状看，仍有四个关键缺口：

1. 运行时图未携带变量定义与默认值，Blackboard 初始状态不可控
2. 执行仍依赖真实时间和异步资源行为，不具备锁步确定性
3. Runner 缺少逐帧 Step、状态快照与回滚恢复能力
4. 缺少可重放的执行事件流与同步安全校验

---

## 版本目标

`v0.8` 的核心目标定义为：

**把技能图运行时升级为“可逐帧驱动、可快照回滚、可确定性回放”的同步基础内核。**

本版本完成后，系统应具备以下能力：

1. 运行时图包含变量定义与默认值，初始状态可重建
2. 支持逐帧 `Step` 执行，不再强依赖“一次 Run 到结束”
3. 支持执行快照导出与恢复，用于断线重同步与回滚
4. 产出结构化执行事件流，用于回放与一致性校验
5. 导出阶段可校验“同步安全节点”，拦截非确定性配置

---

## 本轮范围

### 本轮要做

- 运行时 JSON schema 升级到 `0.8`
- 导出变量定义与默认值
- 新增帧步进 Runner 与快照恢复
- 新增执行事件流（Trace）
- 新增同步安全校验（导出期）
- 补齐确定性与回滚相关测试

### 本轮不做

- 完整网络协议与联网框架
- 预测误差纠正策略（reconcile）
- 多线程并行执行
- 完整图调试器 UI
- 大规模节点体系扩展

---

## 核心方案

## 一、运行时数据契约升级（Schema v0.8）

在 `RuntimeSkillGraph` 中新增同步所需元数据：

- `version = "0.8"`
- `variables: List<RuntimeVariableDef>`
- `syncMode: Lockstep / LocalOnly`
- `deterministicFlags`（可选）

`RuntimeVariableDef` 最小字段：

- `name`
- `valueType`
- `defaultValue`

导出要求：

- 编辑器 `SkillGraphData.variables` 全量导出到运行时图
- 导出期完成默认值合法性校验（Int/Float/Bool 可解析）

兼容策略：

- 加载 `0.6/0.7` 图时，变量列表允许为空并走兼容路径
- 新导出统一写 `0.8`

---

## 二、执行模型升级为逐帧 Step

新增 Runner 执行入口：

- `Initialize(graph, context, options)`
- `Step(frameIndex, frameInput)`
- `GetSnapshot()`
- `Restore(snapshot)`

语义约束：

- 单次 `Step` 仅推进有限节点，避免同帧无限推进
- `Delay` 改为帧计数推进（或统一逻辑时钟），不直接依赖真实毫秒
- `Action` 在同步模式下不直接触发非确定性资源行为，而是发出命令事件

保留能力：

- 兼容原有 `Run` 入口，内部可基于 `Step` 循环实现

---

## 三、快照与回滚能力

新增 `SkillExecutionSnapshot`，至少包含：

- 当前执行节点 ID
- 当前执行状态（Running/Success/Failure/Cancelled）
- 已执行步数
- Blackboard 全量状态
- 节点局部等待态（如 Delay 剩余帧）
- 随机种子与随机游标（若启用）

恢复规则：

- `Restore(snapshot)` 后，后续 `Step` 结果应与原时间线一致
- 快照必须可序列化，支持存档和网络传输

---

## 四、执行事件流（Trace）标准化

新增统一事件结构 `SkillExecutionEvent`，用于回放与一致性校验。

建议事件类型：

- `NodeEnter`
- `NodeExit`
- `BlackboardSet`
- `BranchTaken`
- `CommandIssued`
- `ExecutionEnd`

事件字段至少包含：

- `frameIndex`
- `nodeId`
- `eventType`
- `payload`

用途：

- 回放还原
- 错位排查
- 线上一致性比对

---

## 五、同步安全约束与导出校验

为节点增加同步安全分类：

- `Deterministic`: 可直接进入锁步逻辑
- `PresentationOnly`: 仅表现层执行，不参与状态裁决
- `Unsafe`: 导出锁步图时禁止

本轮强约束：

- 锁步模式下禁止直接使用真实时间 API 和异步资源加载作为状态判定依据
- 锁步模式下 `ActionNode` 输出“命令事件”而非直接驱动 Unity 资源结果
- 导出器对不安全节点与不合法配置直接报错

---

## 六、Blackboard 初始化与类型一致性

Runner 启动时按 `RuntimeVariableDef` 初始化 Blackboard：

- String -> string
- Float -> float
- Int -> int
- Bool -> bool

类型策略：

- SetVariable/Condition/Branch 必须与变量定义类型一致
- 类型不一致在导出期拦截，不留到运行时崩溃

---

## 七、测试策略（v0.8 必做）

新增四类关键测试：

1. **确定性重复执行**
同一输入、同一种子、多次执行事件流完全一致

2. **快照恢复一致性**
执行到 N 帧保存快照，恢复后继续执行，结果与原时间线一致

3. **回滚一致性**
执行到 N 帧回滚到 M 帧，重放到 N 帧，状态一致

4. **导出校验拦截**
不安全节点或非法变量配置在导出时被明确拦截

---

## 建议实现顺序

1. 升级 `RuntimeSkillGraph` schema 到 `0.8`
2. 导出器接入 `variables/defaultValue` 与同步校验
3. 新增 `SkillExecutionSnapshot` 结构
4. 重构 `SkillGraphRunner` 为 `Initialize + Step + Snapshot`
5. 改造 `Delay/Action` 的同步模式语义
6. 接入 `SkillExecutionEvent` 流
7. 增补单元测试与回归样例
8. 编辑器增加“同步模式校验提示”

## 验收标准

以下条件全部满足视为 `v0.8` 完成：

1. 导出 JSON 版本为 `0.8` 且包含变量定义默认值
2. Runner 支持逐帧 `Step` 执行与 `Snapshot/Restore`
3. 同输入下事件流可重复一致
4. 回滚后重放结果一致
5. 锁步模式下可拦截非确定性配置
6. 旧图可兼容加载，错误提示清晰

---

## 风险与注意点

1. **浮点确定性风险**
跨平台浮点比较可能有偏差，建议后续评估定点数或统一比较策略

2. **行为与表现耦合风险**
`Action` 若同时承担状态与表现，容易破坏确定性，需严格拆分

3. **快照体积风险**
全量快照可能偏大，先确保正确性，再评估增量压缩

4. **兼容成本风险**
`0.6/0.7` 图兼容路径必须有明确迁移与报错策略

---

## 后续版本建议

`v0.9` 可聚焦“网络接入与同步工程化”：

- 帧输入协议定义
- 客户端预测与服务端校正
- 回放文件格式与工具链
- 可视化执行调试器

---

## 一句话结论

`v0.8` 不再以“编辑器体验补齐”为主，而是要把技能图推进到**可同步、可回滚、可重放**的运行时基础层。
