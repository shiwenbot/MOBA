# 技能节点编辑器 v0.7 开发计划

## Context

`v0.6` 把运行时执行语义补齐了——节点执行结果有了明确状态模型，Runner 能区分 Success / Failure / Cancelled，异步节点的完成与中断行为统一了。

`v0.7` 回到编辑器本身，补齐日常使用的基础体验。当前编辑器存在以下问题：

1. **Delete 键删除不完整**：选中节点按 Delete 键时，节点被删除但相连的边残留在画布上；右键菜单删除则正常
2. **没有撤销能力**：所有操作都无法撤销，误操作只能手动恢复或重新加载
3. **没有 Blackboard 面板**：运行时有完整的 `SkillBlackboard`，但编辑器里 SetVariableNode 只能手写字段名，看不到图中定义了哪些变量
4. **没有小地图**：节点多了之后无法快速定位和导航

---

## 版本目标

**让编辑器从"勉强能用"升级为"日常可用"。**

本版本完成后，编辑器应具备以下能力：

1. Delete 键删除节点时，相连的边一并清理
2. Ctrl+Z / Ctrl+Y 支持撤销/重做
3. 侧边栏 Blackboard 面板，可以管理图中变量（创建/编辑/删除）
4. 节点的变量名字段从下拉列表选择已定义变量
5. 右下角小地图，支持快速导航

---

## 本轮范围

### 本轮要做

- 修复 Delete 键删除不清理 Edge 的 bug
- 实现基于快照的 Undo/Redo 系统
- 实现 Blackboard 侧边栏面板
- 节点属性字段联动 Blackboard 变量
- 添加小地图

### 本轮不做

- 移动节点位置变更的撤销
- 右键上下文菜单增强
- 复制粘贴功能
- 节点注释/分组
- 执行调试可视化

## 核心方案

## 一、修复 Delete 键删除不清理 Edge

### 问题根因

`SkillGraphView.OnKeyDown` 中手动从 `selection` 收集 `GraphElement` 列表，调用 `DeleteElements(elementsToDelete)` 删除。

`DeleteElements` 只删除传入的元素，不会自动清理与节点相连的边。而右键菜单删除走的是 GraphView 内置的 `DeleteSelection()` 方法，会先收集关联边再统一删除。

### 修复思路

将 `DeleteElements(elementsToDelete)` 替换为内置的 `DeleteSelection()`。

---

## 二、实现 Undo/Redo 系统

### 设计选型：快照命令模式

不使用 `UnityEditor.Undo`（要求操作对象是 `UnityEngine.Object`，节点是纯 UIElements）。改为在关键操作前记录整个图的完整快照（`SkillGraphData` 的 JSON），撤销时恢复快照。

选择理由：
- 当前已有完整的序列化/反序列化能力
- 不需要改造节点为 ScriptableObject
- 图规模小，快照数据量可控

### SkillGraphUndoSystem（新建）

- 撤销栈 + 重做栈（`Stack<string>`，存 JSON 快照）
- `Record(string snapshotJson)`：压入撤销栈，清空重做栈
- `Undo(string currentSnapshotJson)`：弹出撤销栈，当前状态压入重做栈，返回目标快照
- `Redo(string currentSnapshotJson)`：弹出重做栈，当前状态压入撤销栈，返回目标快照
- 最大历史深度 50 步

### 接入点

| 操作 | 记录时机 |
|------|---------|
| 创建节点 | `CreateNode` 调用后 |
| 删除节点/边 | `OnKeyDown` 删除前 |
| 连接端口 | `graphViewChanged` 检测新增 Edge |
| 断开端口 | `graphViewChanged` 检测移除 Edge |
| Blackboard 变量变更 | 变量增删改时 |

### 循环保护

恢复快照时设置 `_isRestoring` 标志位，`graphViewChanged` 中检查该标志位跳过记录，避免循环触发。

## 三、Blackboard 侧边栏面板

### 数据模型

新建 `SkillVariableDef`：

```
SkillVariableDef
  ├── name: string          // 变量名
  ├── type: SkillVarType    // String / Float / Int / Bool
  └── defaultValue: string  // 默认值的字符串表示
```

`SkillGraphData` 新增 `List<SkillVariableDef> variables` 字段。

### 布局

```
┌──────────────────────────────────────────────────┐
│ Toolbar: [New] [Save] [SaveAs] [Load] [Export]   │
├────────────┬─────────────────────────────────────┤
│ Blackboard │                                     │
│ ┌────────┐ │           GraphView                 │
│ │+ 添加   │ │                                     │
│ ├────────┤ │        （节点编辑区域）                │
│ │hp  Int  │ │                                     │
│ │  0      │ │                                     │
│ ├────────┤ │                                     │
│ │name Str │ │                                     │
│ │  ""     │ │                                     │
│ ├────────┤ │                          ┌────────┐ │
│ │isAlive  │ │                          │MiniMap │ │
│ │Bool true│ │                          └────────┘ │
│ └────────┘ │                                     │
└────────────┴─────────────────────────────────────┘
```

面板固定 200px 宽度。

### SkillGraphBlackboardPanel（新建）

- `ListView` 展示变量列表
- 每行：变量名（TextField）+ 类型（EnumField）+ 默认值（TextField）+ 删除按钮
- 顶部添加变量按钮
- 变更时通知 Editor 记录 Undo 快照

### 节点联动

以下节点的变量名字段改为 `PopupField`，数据源来自 `SkillGraphData.variables`：

- **SetVariableNode**：变量名下拉选择
- **ConditionNode**：变量名下拉选择
- **BranchNode**：变量名下拉选择

## 验证方法

1. **删除修复**：创建两个节点连线 → 选中节点按 Delete → 节点和边都消失
2. **Undo/Redo**：创建节点 → Ctrl+Z → 节点消失；Ctrl+Y → 节点恢复
3. **Undo 删除**：删除节点 → Ctrl+Z → 节点和边都恢复
4. **Undo 连线**：连接两个端口 → Ctrl+Z → 连线消失
5. **Blackboard**：添加变量 → 保存 → 重新加载 → 变量列表仍在
6. **节点联动**：在 Blackboard 定义变量 → 创建 SetVariableNode → 变量名下拉列表显示已定义变量
7. **小地图**：打开编辑器 → 右下角出现缩略图 → 拖动小地图中的视口矩形可以移动画布

## 风险与注意点

### 1. 快照恢复会重建所有节点

调用 `DeserializeGraph` 恢复快照时会 ClearGraph 再重建，撤销后节点引用全部替换。当前图规模小，不是问题。

### 2. graphViewChanged 循环触发

恢复快照时设置 `_isRestoring` 标志位，`graphViewChanged` 中跳过记录。

### 3. Blackboard 变量删除后节点引用失效

删除 Blackboard 中的变量时，已引用该变量的节点不会自动清除引用。本轮暂不处理，节点下拉列表中不存在的变量名以纯文本显示。

### 4. MiniMap 和 Blackboard 布局共存

Blackboard 面板在 EditorWindow 层级，MiniMap 在 GraphView 内部，两者不冲突。
