# 技能节点编辑器 v0.2 开发计划

## 评估结论

v0.1 的判断基本正确：当前编辑器只有 GraphView、单一节点、基础连线和删除，确实还不能产出可用的技能图数据。

但原计划里有 3 个点不够合理，需要先修正：

1. `Dictionary<string, string> properties` 不适合作为 Unity `JsonUtility` 的主存储结构。
   结论：改为 `List<SkillNodePropertyData>`，避免序列化失效。

2. `inputPorts` / `outputPorts` 不应该作为节点存档的主数据。
   结论：端口结构由 `nodeType` 决定，存档只保留节点基础信息和边连接信息。

3. Copy/Paste/Duplicate 不能算“顺手实现”。
   结论：它依赖 GraphView 剪贴板协议和选区序列化细节，本轮先降级，不阻塞 Save/Load 主线。

**修正后的 v0.2 目标**：完成“节点类型化 + 图数据保存加载”闭环，确保编辑器能稳定创建、保存、加载和恢复技能图。

---

## 优先级分析

| 方向 | 优先级 | 理由 |
|------|--------|------|
| **数据持久化（Save/Load）** | P0 | 没有保存能力，编辑器产出无法落地 |
| **节点类型体系** | P0 | 没有类型化节点，图无法表达技能逻辑 |
| **节点属性 UI** | P1 | 节点没有参数就无法配置行为 |
| **图文件管理（New / Save As / Load）** | P1 | 提升可用性，降低测试成本 |
| **Copy/Paste/Duplicate** | P2 | 重要，但不应阻塞 v0.2 主线 |
| **导出为运行时配置** | P2 | 依赖图数据结构稳定后再做 |
| **Blackboard / 运行时执行** | P3 | 下一阶段能力 |

## 实现步骤

### 第 1 步：定义可序列化图数据模型

**目标**：建立可被 `JsonUtility` 稳定保存的图结构

创建 `SkillGraphData.cs`：
- `string graphName`
- `List<SkillNodeData> nodes`
- `List<SkillEdgeData> edges`

创建 `SkillNodeData.cs`：
- `string guid`
- `string title`
- `string nodeType`
- `Vector2 position`
- `List<SkillNodePropertyData> properties`

创建 `SkillEdgeData.cs`：
- `string outputNodeGuid`
- `string outputPortName`
- `string inputNodeGuid`
- `string inputPortName`

创建 `SkillNodePropertyData.cs`：
- `string key`
- `string value`

**约束**：
- 不存储端口列表，端口由节点类型生成
- 属性统一按字符串存储，节点自己负责解析为 `enum` / `float`

**文件路径**：`Assets/Editor/SkillGraph/Data/`

---

### 第 2 步：建立节点类型体系

**目标**：把“单一通用节点”升级为可区分职责的基础节点

节点类型：

| 类型 | 说明 | 输入 | 输出 | 属性 |
|------|------|------|------|------|
| **EntryNode** | 技能入口 | 无 | Next | 无 |
| **ActionNode** | 执行动作 | In | Out | `actionType`、`value` |
| **ConditionNode** | 条件分支 | In | True / False | `conditionType`、`compareValue` |
| **DelayNode** | 延时等待 | In | Out | `duration` |

实现方式：
- `SkillGraphNode` 改为节点基类，不再直接实例化
- 每个节点类型独立类，自己声明端口和属性 UI
- 引入 `SkillFlowPort` 作为流程端口类型标记，避免和未来数据端口混淆
- 节点提供 `GetNodeData()` / `ApplyNodeData()` 接口

**文件路径**：`Assets/Editor/SkillGraph/Nodes/`

---

### 第 3 步：节点属性 UI

**目标**：节点参数可以直接在节点内编辑，并可参与序列化

- ActionNode：`EnumField + FloatField`
- ConditionNode：`EnumField + FloatField`
- DelayNode：`FloatField`
- 修改字段后只更新节点内部状态
- 保存时由节点统一写入 `properties`
- 加载时由节点从 `properties` 恢复字段值

---

### 第 4 步：Save / Load / New 工具栏

**目标**：窗口具备完整的图文件操作能力

在 `SkillGraphEditor.cs` 增加工具栏：
- `New`：清空当前画布
- `Save`：已有目标文件则直接覆盖，否则走另存为
- `Save As`：保存到 `Assets/Editor/SkillGraph/Data/` 下的 json 文件
- `Load`：从 json 文件恢复图

在 `SkillGraphView.cs` 增加：
- `SerializeGraph(string graphName)`
- `DeserializeGraph(SkillGraphData data)`
- `ClearGraph()`

实现约束：
- 节点 GUID 用 `GUID.Generate().ToString()`
- 连线恢复依赖 `guid + portName`
- JSON 需要可读、可提交版本控制

---

### 第 5 步：搜索窗口扩展

**目标**：右键菜单可以创建所有基础节点

- 修改 `SkillGraphSearchWindow.cs`
- 分组展示 Entry / Action / Condition / Delay
- 每个菜单项创建对应节点实例

---

## 本轮不纳入实现

- Copy / Paste / Duplicate
- Blackboard
- 运行时导出和执行
- Undo / Redo

这些能力保留到 v0.3+，等图结构稳定后再做。

## 验证方式

1. 打开编辑器后，右键可创建 4 种节点。
2. EntryNode 只有输出端口。
3. ConditionNode 有 `True / False` 两个输出端口。
4. ActionNode / ConditionNode / DelayNode 的字段可以编辑。
5. 点击 `Save As` 保存 json 后，关闭窗口重新打开，`Load` 后节点和连线恢复。
6. 保存的 json 可读，且节点属性被正确写入。
