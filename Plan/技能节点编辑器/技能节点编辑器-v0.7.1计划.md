# 技能节点编辑器 v0.7.1 开发计划（修订）

## Context

`v0.7` 的方向正确，但执行层面有三个关键缺口：

1. Undo 记录时机描述不一致（前/后混用），容易出现第一次 Ctrl+Z 无效
2. 变量下拉联动的改造落点写在 `NodeFactory`，与真实代码结构不符
3. Undo 覆盖面未包含节点属性编辑，用户体验会断裂

`v0.7.1` 保留原目标，修正实现细节，确保方案可落地且行为可预期。

---

## 版本目标

在不扩大范围的前提下，交付一个“日常可用”的编辑器：

1. Delete 删除节点时自动清理关联边
2. Ctrl+Z / Ctrl+Y 可稳定撤销/重做：节点增删、连线变更、Blackboard 变更、节点属性编辑
3. 提供左侧 Blackboard 面板管理变量（增删改）
4. SetVariable / Condition / Branch 节点的 Key 字段支持从变量列表选择
5. 右下角 MiniMap 支持导航

---

## 本轮范围

### 本轮要做

- 修复 Delete 键删除不清理 Edge
- 实现快照时间线式 Undo/Redo
- 实现 Blackboard 面板与变量序列化
- 实现变量下拉联动（节点层改造）
- 添加 MiniMap

### 本轮不做

- 节点拖拽过程的连续轨迹撤销优化（仅保证最终位置可撤销）
- 复制粘贴、分组、注释
- 调试可视化

## 核心修订方案

## 一、Delete 修复

`SkillGraphView.OnKeyDown` 中，删除逻辑统一改为 `DeleteSelection()`，不再手动 `DeleteElements(...)`。

同时增加输入态保护：当焦点在输入控件（如 `TextField/IntegerField/FloatField`）时，不消费 Delete 快捷键，避免误删节点。

---

## 二、Undo/Redo（快照时间线）

### 2.1 统一语义

采用“**操作完成后记录快照**”的时间线模型，并在图加载/新建后记录基线快照。

- Undo 栈：按时间顺序保存状态快照（栈顶=当前状态）
- Redo 栈：保存被撤销的状态

行为定义：

- `Record(snapshot)`：若与当前栈顶相同则忽略；否则压入 Undo 栈，并清空 Redo 栈
- `Undo()`：若 Undo 栈数量 <= 1，不可撤销；否则弹出当前状态到 Redo 栈，返回新的 Undo 栈顶用于恢复
- `Redo()`：若 Redo 栈为空，不可重做；否则弹出并压入 Undo 栈，返回该状态用于恢复

> 该模型可避免“创建后记录导致第一次 Undo 无效”的问题。

### 2.2 覆盖的记录点

- 新建节点（SearchWindow 选节点后）
- 删除节点/边（Delete、右键删除）
- 建立连线 / 断开连线（`graphViewChanged`）
- 节点属性字段变化（Key / ValueType / Value / Action 等）
- Blackboard 变量增删改
- 新建图、加载图后写入基线快照

### 2.3 循环保护

恢复快照时设置 `_isRestoring = true`，期间禁止触发任何 `Record(...)`；恢复结束后重置。

---

## 三、Blackboard 侧边栏

### 3.1 数据模型

新增 `SkillVariableDef`：

- `name: string`
- `type: SkillBlackboardValueType`（复用现有枚举）
- `defaultValue: string`

`SkillGraphData` 增加：

- `List<SkillVariableDef> variables`

### 3.2 面板行为

新建 `SkillGraphBlackboardPanel`（固定宽度 200）：

- `ListView` 渲染变量项
- 每项支持改名、改类型、改默认值、删除
- 顶部“添加变量”
- 任何变更触发图数据更新与 Undo 记录

---

## 四、节点变量联动（落点修正）

联动改造不放在 `SkillGraphNodeFactory`，而放在节点类与基类事件机制：

- `SkillGraphNode` 增加属性变更通知事件（供 Editor 记录 Undo）
- `SetVariableNode` / `ConditionNode` / `BranchNode` 的 Key 字段由 `TextField` 改为“可下拉选择 + 保留旧值回显”的控件策略

回显规则：

- 变量存在：显示为下拉选中项
- 变量已删除但节点仍引用旧值：显示旧字符串（不自动清空），并允许用户重新选择

---

## 五、MiniMap

在 `SkillGraphView` 内集成 `MiniMap`，定位右下角，避免与 EditorWindow 左侧 Blackboard 容器重叠。

---

## 验证方法（新增关键用例）

1. 删除节点后边一并消失（Delete 与右键都一致）
2. 新建节点后 Ctrl+Z 立即可撤销，Ctrl+Y 可恢复
3. 连线后 Ctrl+Z 连线消失，Ctrl+Y 恢复
4. 修改节点 Key/Value 后 Ctrl+Z 可回退字段值
5. Blackboard 变量增删改可撤销/重做
6. 保存并重载后，variables 完整保留
7. 节点引用已删除变量时保留旧值回显，不崩溃
8. 文本输入焦点下按 Delete 不误删节点
9. MiniMap 可拖动视口并正确导航

---

## 风险与注意点（修订）

1. 快照恢复会重建节点实例，节点引用不可跨恢复周期持有
2. 字段频繁输入会产生大量快照，建议做 150~300ms 防抖记录
3. 变量重命名暂不做“全图自动重命名引用”，保持显式人工确认
4. 若图体量增长明显，后续再评估从全量快照切换增量命令
