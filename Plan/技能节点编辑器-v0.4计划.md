# 技能节点编辑器 v0.4 开发计划
## Context

当前 `v0.3` 已经打通了最小运行时闭环：

- 编辑器可以创建并导出运行时 JSON
- 运行时可以加载技能图并顺序执行
- 当前已支持 `Entry / Debug / Delay` 三种运行时节点

已经验证的链路是：

`Entry -> Debug("开始") -> Delay(1s) -> Debug("结束")`

这证明了图编辑、导出、反序列化、运行时调度这条主链路已经成立。  
当前缺的不是“还能不能再做一个编辑器功能”，而是“能不能让图真正驱动可见的角色表现”。

上一版 `v0.4` 计划偏向通用 `ActionNode` 运行时扩展，但随着项目中已经引入 `Animancer`，以及你希望：

- 手动给脚本引用 AnimationClip
- 动画节点支持在编辑器里拖 prefab

那么更合理的实现方式应该调整为：

**让 `PlayAnimation` 先走一条最短闭环：节点拖 prefab，prefab 上挂 Animancer 播放脚本，运行时实例化 prefab 并直接播指定 clip。**

这样可以避免当前阶段过早把技能系统做成一套复杂动作总线，也能绕开 Animator Controller 状态维护问题。

---

## 版本目标

`v0.4` 的主目标调整为：

**完成 `PlayAnimation` 的 Animancer MVP 闭环。**

目标链路：

1. 在技能图中创建 `ActionNode`
2. 将 `ActionType` 设为 `PlayAnimation`
3. 在节点中拖入一个 prefab
4. prefab 上挂一个轻量的 Animancer 播放脚本，并在 Inspector 手动指定 `AnimationClip`
5. 运行时执行到该节点时，实例化 prefab 并播放 clip

本轮的最终演示目标：

**让 `Darius.prefab` 在运行时播放一次 `Dance`。**

---

## 为什么改成这个方案

### 1. 这条路径最短

如果运行时直接管理：

- prefab 资源
- clip 资源
- Animator / Controller 状态
- clip 名字与状态名映射

那一上来就会把 `ActionNode` 的设计复杂化。  
而 Animancer 的核心能力正好是绕过 Animator Controller 直接播放 clip。

当前包里已经有 `Animancer 8.2.2`，其最直接的使用方式就是：

```csharp
animancer.Play(animationClip);
```

因此，本轮最优路线不是扩展一套通用动作框架，而是先把 `PlayAnimation` 做实。

### 2. prefab 挂脚本，能把动画细节留在资源侧

你提出“写一个脚本，我手动引用对应的 animation clip”，这个思路是对的。  
它的优势是：

- 技能图只负责“播哪个 prefab”
- 动画 clip 绑定由 prefab 自己维护
- 不需要把 Unity 对象引用直接塞进运行时 JSON
- 节点数据更稳定，资源职责更清晰

### 3. 编辑器拖 prefab 比拖 clip 更适合当前数据模型

当前技能图保存的是 JSON，不适合直接保存 UnityEngine.Object 引用。  
因此编辑器层面可以支持拖拽 prefab，但最终落盘时应该保存的是：

- prefab 的 AssetPath
- 或 prefab 的 GUID
- 或导出后的 runtime location

而不是直接保存 Object 引用。

---

## 本轮范围

### 本轮要做

- `ActionNode` 正式纳入运行时支持
- `ActionType.PlayAnimation` 打通
- 动画节点支持拖拽 prefab
- 导出器支持把 prefab 引用转换成运行时可加载地址
- 新增一个 prefab 侧的 Animancer 播放脚本
- 运行时执行 `PlayAnimation` 时实例化 prefab 并播放 clip

### 本轮不做

- `ConditionNode` 运行时支持
- Blackboard
- 多分支执行
- `SpawnEffect`
- `ApplyDamage`
- 服务端权威执行
- 预测 / 回滚
- 图调试器
- Undo / Redo
- Copy / Paste / Duplicate
- 动画节点直接拖 clip 到图里并运行时通用解析

本轮只做一件事：

**把 PlayAnimation 跑通。**

---

## 核心方案

## 一、运行时节点继续沿用 ActionNode

不新增独立 `PlayAnimationNode`，仍然使用现有 `ActionNode`，但把它的 MVP 范围收敛为：

- 当前只保证 `PlayAnimation` 可用

这能保留后续扩展空间，同时避免节点种类过早膨胀。

---

## 二、prefab 上新增 Animancer 播放脚本

新增一个轻量组件，例如：

- `SkillGraphAnimancerPlayer`

职责只做一件事：

- 持有一个 `AnimationClip`
- 保证物体上存在 `AnimancerComponent`
- 在外部调用时执行 `AnimancerComponent.Play(_clip)`

建议序列化字段：

- `AnimationClip _clip`
- `float _fadeDuration = 0.25f`
- `bool _destroyOnEnd = false`

可选增强字段：

- `Vector3 _spawnOffset`
- `bool _faceCamera`

但这些不是本轮必须项。

### 推荐最小接口

```csharp
public void Play();
```

或：

```csharp
public void Play(float fadeDurationOverride = -1f);
```

本轮建议保持简单，先只要 `Play()`。

---

## 三、Animancer 使用方式

根据当前包内 API，最直接的调用方式是：

```csharp
AnimancerComponent animancer = GetComponent<AnimancerComponent>();
animancer.Play(animationClip);
```

这意味着脚本不需要 Animator Controller 状态机，也不需要硬编码状态名。  
这正好适合 `Darius.prefab` 这类“模型和 clip 已经存在，但不想维护 controller 状态”的场景。

### 注意点

- `AnimancerComponent` 需要绑定到目标 `Animator`
- `AnimationClip` 必须是合法可播放的 clip
- 如果 prefab 上已经有 Animator，Animancer 直接驱动它即可

---

## 四、ActionNode 编辑器改造

当前 `ActionNode` 已经有：

- `actionType`
- `value`

这不足以表达“播放哪个 prefab”。  
因此本轮需要给 `ActionNode` 增加一个 prefab 资源字段。

### 编辑器侧新增字段

建议新增：

- `prefabAssetPath`

编辑器 UI 使用：

- `ObjectField`，类型限制为 `GameObject`

交互方式：

1. 在节点中拖入一个 prefab
2. 内部通过 `AssetDatabase.GetAssetPath(prefab)` 记录路径
3. 保存图时写入 `properties`
4. 加载图时通过路径恢复 `ObjectField`

### 为什么保存 path 而不是 Object 引用

因为技能图当前是 JSON 存档，Object 引用无法直接稳定跨运行时保存。  
因此应该采用：

- 编辑器显示 Object
- 数据层只保存路径 / GUID / address

这是一种典型的“编辑器引用，运行时字符串化”的做法。

---

## 五、导出策略

编辑器存图和运行时导出应区分对待。

### 编辑器图数据

建议保留：

- `actionType`
- `value`
- `prefabAssetPath`

### 运行时导出数据

导出时不要再保留编辑器专用路径，而应转换为运行时地址，例如：

- `prefabLocation = "Actor/Darius"`

或按项目资源规则生成其它 location。

### 导出阶段职责

导出器负责：

1. 校验 `ActionNode` 是否配置 prefab
2. 将 `prefabAssetPath` 转换为 runtime location
3. 只把运行时真正需要的信息写入导出 JSON

这样运行时就不依赖 `AssetDatabase`。

---

## 六、运行时执行策略

`ActionNodeHandler` 本轮只保证处理：

- `PlayAnimation`

运行逻辑建议如下：

1. 读取 `actionType`
2. 如果不是 `PlayAnimation`，直接报未支持
3. 读取 `prefabLocation`
4. 运行时加载并实例化 prefab
5. 找到 `SkillGraphAnimancerPlayer`
6. 调用 `Play()`
7. 返回 `Out`

### prefab 缺少播放脚本时

应明确报错，而不是静默失败。  
错误信息建议包含：

- 节点 ID
- prefabLocation
- 缺失的组件名

---

## 数据约定

### 编辑器图存档建议

```json
{
  "nodeType": "Action",
  "properties": [
    { "key": "actionType", "value": "PlayAnimation" },
    { "key": "value", "value": "1" },
    { "key": "prefabAssetPath", "value": "Assets/AssetRaw/Actor/Darius.prefab" }
  ]
}
```

### 运行时导出建议

```json
{
  "nodeType": "Action",
  "properties": [
    { "key": "actionType", "value": "PlayAnimation" },
    { "key": "value", "value": "1" },
    { "key": "prefabLocation", "value": "Actor/Darius" }
  ]
}
```

### 本轮约束

- `actionType` 必须存在
- `prefabAssetPath` 在编辑器图中不能为空
- `prefabLocation` 在运行时导出中不能为空
- prefab 上必须挂 `SkillGraphAnimancerPlayer`
- `SkillGraphAnimancerPlayer` 上必须配置 `AnimationClip`

## 实施步骤

### Phase 1：ActionNode 编辑器支持 prefab 拖拽

目标：让节点能配置一个 prefab

工作项：

- 在 `ActionNode` 中增加 `ObjectField`
- 保存 `prefabAssetPath`
- 加载图时恢复该字段

完成标准：

- 节点中可拖拽 prefab
- Save / Load 后数据不丢失

### Phase 2：新增 prefab 侧 Animancer 播放脚本

目标：把动画播放能力封装到 prefab 自身

工作项：

- 新增 `SkillGraphAnimancerPlayer`
- 自动获取或绑定 `AnimancerComponent`
- 支持调用 `Play()`

完成标准：

- 给任意 prefab 挂上该脚本并指定 clip 后，可单独触发播放

### Phase 3：导出器支持 PlayAnimation

目标：让图中 prefab 配置能转换为运行时可用数据

工作项：

- 导出器支持 `SkillNodeType.Action -> RuntimeNodeTypes.Action`
- 校验 `PlayAnimation` 必须配置 prefab
- 将 `prefabAssetPath` 转换为 `prefabLocation`

完成标准：

- 配好 prefab 的 `ActionNode` 可以导出
- 非法配置会在导出时报错

### Phase 4：运行时支持 ActionNode

目标：让 `PlayAnimation` 在运行时执行

工作项：

- 新增 `RuntimeNodeTypes.Action`
- 注册 `ActionNodeHandler`
- 运行时实例化 prefab 并调用 `SkillGraphAnimancerPlayer.Play()`

完成标准：

- 运行时执行到该节点时可以看到对象出现并开始播放动画

### Phase 5：Darius Dance 验证

目标：完成本轮最终验收样例

工作项：

1. 给 `Darius.prefab` 挂 `SkillGraphAnimancerPlayer`
2. 在脚本中手动引用 `Dance` clip
3. 在技能图中创建：
   `Entry -> Action(PlayAnimation, Darius.prefab)`
4. 导出并运行

完成标准：

- 运行时实例化 `Darius.prefab`
- `Dance` 成功播放

## 验收标准

以下条件全部满足，即视为 `v0.4` 完成：

1. `ActionNode` 可以在编辑器中拖拽 prefab
2. 保存、加载后 prefab 配置能正确恢复
3. 导出器能把 prefab 配置转换成运行时地址
4. 运行时能识别并执行 `ActionNode`
5. prefab 上的 Animancer 播放脚本能正常工作
6. `Darius.prefab` 能在运行时播放一次 `Dance`

---

## 风险与注意点

### 1. 不要把 Unity Object 直接塞进运行时 JSON

编辑器阶段可以用 `ObjectField`，  
但落盘和导出时必须转换成字符串标识。

### 2. prefab 的动画配置应留在资源侧

本轮不要让技能图直接管理 clip 细节。  
技能图只决定“播哪个 prefab”，具体播哪段动画由 prefab 上的 `SkillGraphAnimancerPlayer` 决定。

### 3. 运行时只做最小实例化，不做复杂生命周期管理

本轮只需要看到 `Darius` 出现并播放 `Dance`。  
对象复用、回收、池化、持续驻留策略都可以延后。

### 4. Animancer 依赖 Animator

虽然不依赖 Animator Controller 状态机，  
但仍然需要目标对象上有可驱动的 `Animator`。

---

## 后续版本建议

`v0.4` 完成后，下一个自然版本建议是：

**v0.5：动画节点参数化**

可以继续扩展：

- 让动画节点支持拖 prefab 之外，再支持配置播放策略
- 支持同 prefab 多动画
- 支持播放完成销毁
- 支持 SpawnEffect / ApplyDamage
- 再之后才进入 `Condition + Blackboard`

---

## 一句话结论

`v0.4` 的正确落地方向是：

**动画节点拖 prefab，prefab 上挂 Animancer 播放脚本并手动引用 clip，运行时实例化后直接播放。**
