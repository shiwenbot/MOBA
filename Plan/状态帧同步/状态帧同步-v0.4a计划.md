# 状态帧同步-v0.4a计划：Box2D 物理集成与 MOBA 式移动阻挡

## Context

`v0.3c` 已完成全局帧号、快照回滚、逐帧重播和输入缓冲闭环控制，当前主线路径已经具备：

- 服务端 30Hz 权威推进
- 客户端只预测自己
- 基于快照的状态恢复、一致性检查与正式回滚

进入 `v0.4a` 后，主线从“把物理状态纳入快照/回滚链路”进一步演化为“明确普通移动的语义”。本阶段的关键发现是：

- 服务端会同时推进所有玩家的物理体
- 客户端预测缓存本质上仍然只覆盖自己
- 如果普通移动中保留玩家-玩家真实动态互推，那么本地结果会依赖“其他玩家未来几帧怎么走”
- 这与“客户端只预测自己”的 MOBA 主流路线结构性冲突，会直接放大 `MISMATCH/ROLLBACK`

因此，`v0.4a` 的目标不是把普通英雄移动做成真实动态刚体互推，而是落成更接近 LoL / 常规 MOBA 的移动模型：

- 地图/静态障碍继续走物理阻挡
- 玩家之间保留碰撞、占位、卡位、窄口 body block
- 普通移动不再产生持续动量传递
- 显式位移效果留给后续技能逻辑单独处理

- 状态：`进行中（共享物理层与客户端回滚链路已落地）`
- 更新日期：`2026-05-17`

## 目标

- 将 `BattleWorldSnapshot` 从“逻辑状态快照”升级为“逻辑状态 + 物理状态”的统一快照。
- 让服务端与客户端都在固定 `dt = 33.333ms` 下推进 Box2D 世界，并支持快照恢复。
- 保持“客户端只预测自己”的主线不变。
- 将玩家-玩家普通移动从“真实动态互推”改为“确定性占位/分离”。
- 保留地图静态碰撞与后续显式位移技能的扩展空间。

## 非目标

- 本阶段不实现技能位移、击退、拉拽、冲锋等显式位移玩法。
- 本阶段不处理断线重连、异常网络降级或完整脏同步裁剪策略。
- 本阶段不引入动态仿真速率调整。
- 本阶段不把远端玩家升级为完整全量预测体。

---

## 设计约束

1. **固定步长不变**  
   Box2D `Step` 始终使用 `33.333ms`，追帧时只能增加 Tick 次数，不能修改仿真 `dt`。

2. **回滚坐标系不变**  
   回滚仍以全局逻辑帧号为唯一坐标系，逻辑状态和物理状态必须共用同一 `FrameIndex`。

3. **快照是唯一恢复来源**  
   权威校正和回滚恢复必须走“权威快照 + 输入历史 + 逐帧重播”，不能只改玩家坐标而留下旧物理状态。

4. **普通移动不做真实互推**  
   玩家之间允许接触、卡位、最小分离距离与窄口阻挡，但普通移动不应把对方连续顶着滑走。

5. **客户端继续只预测自己**  
   远端玩家在本地是权威快照驱动的代理体，不依赖未来输入做完整预测。

## 实现步骤

### Step 0：补齐共享快照骨架

- 将 `BattleWorldSnapshot.PhysicsSnapshot` 升级为强类型物理快照。
- 新增 `PhysicsWorldSnapshot`、`PhysicsBodySnapshot`、`PhysicsContactSnapshot`。
- 为 `BattleWorldState` 增加物理世界恢复能力。
- 扩展 `StateHasher`，让物理状态进入统一哈希。

状态：`已完成`

### Step 1：抽象 Box2D 世界适配层

- 引入 `FrameSyncPhysicsWorld` 与 `IPhysicsMovementWorld`。
- 明确“逻辑玩家实体 ↔ 物理 bodyId”的一一映射。
- 提供 `EnsureBody`、`SetBodyMovementInput`、`Step`、`TakeSnapshot`、`RestoreSnapshot` 等统一接口。

状态：`已完成`

### Step 2：服务端接入物理推进

- `BattleLogic` 每帧先喂输入，再统一 `Step`，最后从物理世界回写玩家状态。
- 广播快照时携带物理刚体与接触数据。
- 当前普通移动语义已从“动态互推”切换为“非互推 + 占位/分离”。

状态：`已完成`

### Step 3：客户端接入物理回滚与重播

- 客户端预测路径通过共享物理世界推进。
- 应用权威快照时同时恢复逻辑状态与物理状态，而不是只改玩家位置。
- 回滚重播继续走输入历史逐帧重放。

状态：`已完成`

### Step 4：移动同步切换为更接近 MOBA 的物理结果同步

- 玩家 fixture 不再参与真实动态互推。
- `FrameSyncPhysicsWorld.Step()` 内增加确定性占位/分离逻辑与接触重建。
- 未被本帧预测到的远端玩家默认速度归零，避免旧速度残留继续驱动物理体。
- 保留当前日志与无头测试入口，补充新的碰撞回归用例。

状态：`核心链路已完成，表现层插值与显式位移技能仍待后续阶段继续扩展`

## 当前实现结论

本阶段最新代码已经明确采用以下语义：

- **玩家-玩家普通移动**：有碰撞、有占位、有卡位，但没有持续真实互推
- **玩家-地图/静态障碍**：继续保留物理阻挡方向
- **客户端预测**：继续只预测自己
- **权威校正**：恢复整份 `BattleWorldSnapshot`，包含物理状态
- **回滚风险**：已去掉“只预测自己 + 动态互推”的主要结构性冲突源

这与 LoL 类 MOBA 的常规移动语义一致，也更符合当前工程的预测/回滚架构。
