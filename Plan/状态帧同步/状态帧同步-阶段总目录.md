# 状态帧同步-阶段总目录
## Context

状态帧同步系统需要按多个 Session 分阶段推进，不在一个版本里一次性完成。
本文件作为总目录，只定义阶段目标、阶段边界和每个阶段对应的计划文档。

> 版本线说明：`状态帧同步 v0.x` 与 `技能节点编辑器 v0.x` 为两条独立版本线。  
> 其中技能节点编辑器 `v0.8-A` 的 Step 内核产物是状态帧同步 `v0.5` 的前置依赖。

### 设计原则

1. **确定性验证贯穿始终**：每个版本都包含确定性相关的验证点，而非最后统一处理
2. **帧号策略先验证后锁定**：v0.2 先完成协议 PoC，再确定“服务端分配帧号”或“客户端预测帧号+服务端窗口校验”的最终方案
3. **可视化验证**：MVP 包含可交互的移动同步 demo，直观验证帧同步效果
4. **渐进复杂度**：每个版本控制在 1~2 个核心概念，必要时拆分子阶段，避免跳跃式复杂度增长

---

## 版本路线（总览）

1. **MVP（最小闭环 + 可视化验证）**
2. **v0.2（帧号协议 + 服务端权威帧驱动）**
3. **v0.3（预测 + 一致性检查 + 回滚追帧）**
4. **v0.4（核心子系统脏同步：移动 + 属性）**
5. **v0.5（高级子系统脏同步：Buff + 技能 + 行为树）**
6. **v0.6（异常网络与断线重连）**
7. **v0.7（性能、内存窗口与观测工具）**
8. **v0.8（安全与防作弊）**
9. **v1.0（联调封版与上线基线）**

## 阶段文档目录

### 1. `状态帧同步-MVP计划.md`
- **目标**：单房间、双端 30Hz 固定帧、输入上行与广播回包、同帧执行闭环跑通
- **新增**：包含可视化移动同步 demo（两个客户端控制方块移动），能直观验证帧同步效果
- **确定性验证**：验证相同输入在客户端/服务端产生相同结果的基础条件（无物理、无随机）

### 2. `状态帧同步-v0.2计划.md`
- **目标**：建立帧号协议、输入缓冲、服务端帧驱动与客户端超前帧控制（不含回滚）
- **新增**：帧号协议 PoC（默认优先验证“客户端预测帧号上行 + 服务端窗口校验与确认”）
- **决策点**：若 PoC 证明“服务端分配帧号”收益更高，则在 v0.2 末锁定并在后续阶段统一采用
- **确定性验证**：帧号连续性校验、命令顺序一致性验证

### 3. `状态帧同步-v0.3计划.md`
- **目标**：引入本地预测、一致性检查、回滚与追帧主流程，完成可验证的误差修正链路
- **确定性验证**：默认“关键帧/抽样帧”状态哈希比对（调试开关可切换为逐帧比对）
- **关键产出**：统一的状态快照/恢复机制（避免组件遗漏字段的问题）

### 4. `状态帧同步-v0.4计划.md`
- **目标**：移动同步与属性同步按"指令+脏同步"模型拆分落地
- **范围**：移动（位置/速度/旋转）、属性（血量/蓝量/攻击力等数值属性）
- **确定性验证**：移动和属性的状态一致性精度验证（阈值内判定一致）

### 5. `状态帧同步-v0.5计划.md`
- **目标**：Buff 系统、技能系统（SkillGraph 集成）、行为树黑板按"指令+脏同步"模型落地
- **前置依赖**：v0.4 的脏同步框架 + 技能节点编辑器 `v0.8-A`（Step/Snapshot 最小内核）
- **执行策略**：按优先级分批落地（先 Buff，再技能输入链路，最后行为树黑板），避免单阶段过载
- **确定性验证**：技能执行结果、Buff 叠加/移除的一致性验证

### 6. `状态帧同步-v0.6计划.md`
- **目标**：处理丢包、乱序、长延迟、断线重连、补帧恢复与房间重入
- **重点改进**：完整实现断线重连协议（参考仓库此处为 TODO），分帧追帧避免卡顿
- **确定性验证**：断线重连后状态恢复的完全一致性

### 7. `状态帧同步-v0.7计划.md`
- **目标**：快照与输入缓冲窗口治理、追帧开销控制、监控面板与诊断日志体系
- **重点改进**：历史快照滑动窗口清理（参考仓库的内存泄漏问题）、帧聚合发送优化
- **确定性验证**：长时间运行（30 分钟+）无内存泄漏、无状态漂移

### 8. `状态帧同步-v0.8计划.md`
- **目标**：帧同步链路防作弊（输入频率/归属校验、关键命令审计、异常检测）
- **注**：帧号合法性由 v0.2 锁定后的帧号策略保障，本版本聚焦更高层的反作弊
- **确定性验证**：作弊检测的误报率和漏报率验证

### 9. `状态帧同步-v1.0计划.md`
- **目标**：全链路联调、回归测试、压测指标达标、发布前冻结与验收
- **确定性验证**：全量状态哈希对比、长时间压测稳定性

## 阶段推进规则

1. 每个版本文档必须包含：目标、范围、非目标、实现步骤、验证方式、完成标准。
2. 当前阶段"完成标准"全部满足后，才能进入下一阶段。
3. 每阶段结束时更新本目录中的状态标记：`未开始 / 进行中 / 已完成`。
4. 任何新增需求先归类到现有阶段；若影响主路径，再新增 `v0.x` 文档，不直接改已封版目标。
5. **确定性验证是每阶段的必修项**，不可跳过或延后。
