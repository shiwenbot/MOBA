Context

当前帧同步系统中所有数学运算使用 float。MVP-a 验收时发现 TickAccumulatorTests.Accumulate_Converts60FpsTo30TicksPerSecond 因浮点累积误差失败（60 次 1.0f / 60.0f 累加不等于精确 1.0f）。

项目使用 Fantasy 网络框架的服务端权威 + 客户端预测架构。GameServer（C# 独立进程，可能 Linux）和 Unity Client（多平台）需执行相同物理仿真。以下浮点运算跨平台不可能位级一致：

  • Math.Exp：ShuttlecockPhysics.Step() 每帧 2 次，CRT 实现跨平台不同
  • MathF.Sin：ShuttlecockEntity.ExecuteLaunch() 发射角计算
  • MathF.Sqrt：FrameSyncPhysicsWorld 碰撞法线（本阶段不迁移）
  • 浮点累积：TickAccumulator 时间累积精度丢失

已锁定的设计决策

  1. 帧率：30Hz 逻辑帧（dt = 33.333ms）
  2. 弹道模型：高空气阻力，水平速度指数衰减约 60%/s（不使用 Box2D）
  3. 坐标约定：2.5D 模型——XZ 水平面，Y 独立高度标量
  4. Box2D 范围：羽毛球弹道不走 Box2D，角色移动走 Box2D
  5. 确定性工具链：BitConverter.SingleToInt32Bits 位比较 + DeterminismRules 约束

现有代码能力

  • ShuttlecockPhysics：纯数学弹道（无 Box2D），迁移首选
  • FrameSyncPhysicsWorld：封装 Box2D，内部 System.Numerics.Vector2（float）
  • TickAccumulator：浮点累积器，已有失败测试
  • DeterminismRules：提供 AssertFixedDt / AssertFinite / FloatToBits
  • 快照/回滚：ISnapshotable<T> / SnapshotBuffer<T>，不关心内部数据类型

阶段状态

  • 状态：待实现
  • 前置依赖：MVP-a 已完成（羽毛球弹道物理）
  • 后续衔接：MVP-b（角色移动）、状态帧同步双端验证

目标

  1. 引入定点数库：源码 vendoring 引入 FixedMathSharp（Q32.32），为帧同步确定性奠定基础
  2. 羽毛球弹道迁移：ShuttlecockPhysics + ShuttlecockEntity + CourtConstants 全部 float → Fixed64
  3. 时间累积修复：TickAccumulator 内部 Fixed64 累积，修复已知测试失败
  4. 确定性验证：同进程两次相同输入羽毛球仿真，所有帧状态位级一致

技术决策 (10 TD)

TD-1：引入 FixedMathSharp（Q32.32）— 双端源码 vendoring

采用 FixedMathSharp（MIT），源码放入 GameShared/ThirdParty/FixedMathSharp/，确保 Unity 和 GameServer 编译相同代码。

Fixed64（Q32.32，精度 ~10-10），FixedMath（全部超越函数），Vector2d（2D 向量）。

放在 GameShared asmdef 目录内 → 自动属于 GameShared 程序集。Entity.csproj 现有 <Compile Include="GameShared/**/*.cs"> glob 已覆盖。

Codex v3 P1 修正：asmdef 可见性

原路径 ThirdParty/FixedMathSharp/ 在 GameShared asmdef 之外，GameShared 看不到。改为 GameShared/ThirdParty/FixedMathSharp/，无需额外 asmdef 配置。Entity.csproj 也无需新增行。

方案开发量精度维护
自研 Q16.16高~0.015mm自维护
FixedMathSharp Q32.32低（vendoring）~10-10社区维护

TD-2：数学函数 — FixedMathSharp 内建

Sin/Cos/Tan、Exp/Log/Log2（正确 range reduction：e^x = 2^k × e^r）、Sqrt、Atan2、Pow、Abs/Min/Max/Clamp/Lerp 等。迁移代码直接调用。

TD-3：向量类型 — Vector2d

Vector2d（Fixed64 X + Fixed64 Y），含点积/长度/归一化/距离。不引用 UnityEngine，转换时用 .X.ToDouble() / .Y.ToDouble()。

TD-4：Box2D 边界 — 保留 float，延后到 MVP-b

本阶段不修改 FrameSyncPhysicsWorld。MVP-b 时在 MoveSystem 添加 Fixed64 ↔ float 转换。

TD-5：文件组织 — GameShared/ThirdParty

FixedMathSharp 源码放 GameShared/ThirdParty/FixedMathSharp/（asmdef 内），测试放 GameShared/Tests/FixedPoint/，业务代码留原目录。

TD-6：迁移策略 — 分 5 层渐进

层内容依赖
L1安装 + 验证无
L2CourtConstantsL1
L3ShuttlecockPhysics 全链路L1+L2
L4TickAccumulator + DeterminismRulesL1
L5确定性验证测试L1-L4

TD-7：常量定义 — static readonly Fixed64

const float → static readonly Fixed64。JIT 会内联，性能等价。

TD-8：测试策略 — m_rawValue 直接比较

Fixed64.m_rawValue（public long 字段）直接比较，整数值天然位级一致。确定性自测：两次仿真所有中间状态的 m_rawValue 完全相等。

Codex v3 P2 修正：统一字段名

FixedMathSharp 实际暴露 m_rawValue（public long 字段），不是 RawValue 也不是 Bits。全文统一。

TD-9：ITickable / TickDispatcher 边界 — 保留 float

保持 ITickable.Tick(uint, float)。羽毛球模块入口用预计算的 DeterminismRules.FixedDeltaTimeFixed64 替代 float 参数。TickAccumulator 保持 Accumulate(float) 签名，内部 Fixed64 累积。

TD-10：双端构建一致性 — vendoring 到 GameShared 内部

问题：Entity.csproj 不用 UPM/NuGet，通过 <Compile Include="GameShared/**/*.cs"> 链接源码。UPM 安装对 GameServer 不可见。

方案：源码 vendoring 到 GameShared/ThirdParty/FixedMathSharp/。

  • Unity：asmdef 内，自动可见
  • GameServer：现有 glob 已覆盖，无需新增行
排除方案问题
UPM + NuGet两个包源，版本可能不一致
HotFix/ThirdParty/（GameShared 外）需要单独 asmdef + 引用
编译 DLL增加构建步骤
