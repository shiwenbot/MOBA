# 状态帧同步-v0.0c计划：Box2D 确定性验证

## Context

状态帧同步的核心前提是：相同输入 + 相同初始状态 + 相同固定 dt -> 产生一致的物理结果。  
v0.0a 已验证 Fantasy 网络层能支撑 30Hz 收发，本阶段聚焦验证 Box2DSharp 在服务端与客户端的确定性边界。

关键背景：
- 本项目采用状态帧同步（服务端权威），不是纯 Lockstep。
- 服务端结果是最终真相，客户端预测允许误差，但误差会转化为回滚成本。
- Box2DSharp 使用 `float`，同平台同配置通常可稳定确定，跨运行时/跨后端需要实测。

---

## 目标

- 在固定 dt=1/30s 下验证 Box2DSharp 单平台 bit-exact 确定性。
- 明确定义“完全一致”：逐字段 bit-exact，而非 epsilon 容差。
- 验证服务端（.NET 8/.NET 9）与 Unity（Mono/IL2CPP）各自单平台确定性。
- 输出跨平台差异数据，不作为当前阶段阻塞项。
- 给 v0.3 预测回滚提供可量化输入（偏差、首帧分歧、回滚频率预估）。

---

## 范围

- 引入 Box2DSharp（服务端 + Unity）。
- 构建统一测试场景 `DeterminismTestScenario`（共享代码）。
- 构建状态快照与哈希工具 `PhysicsWorldSnapshot`（共享代码）。
- 实现服务端批量重复仿真与报告导出。
- 实现 Unity 端测试入口（EditMode + IL2CPP Player 对比流程）。

---

## 非目标

- 不实现帧同步 Tick/帧号管理。
- 不实现网络同步流程。
- 不改 Box2DSharp 源码与 float 精度机制。
- 不做完整可视化调试系统（仅可选日志/Gizmos）。

---

## P0 硬性补充：实验环境锁定

为保证“可复现”，每次验证必须记录并锁定：
- 操作系统版本（如 Windows 11 24H2）。
- CPU 架构（x64/ARM64）与指令集信息。
- .NET SDK 精确版本（例如 `8.0.4xx`、`9.0.1xx`）。
- 运行时 TFM（`net8.0` / `net9.0`）。
- Unity 精确版本（例如 `2022.3.xf1`）。
- Unity Scripting Backend（Mono / IL2CPP）。
- Build Configuration（Debug/Release）。
- Box2DSharp 精确版本号（禁止“最新稳定版”描述）。

说明：
- 版本一旦用于基线报告，后续不得静默升级；升级必须触发一次完整回归。

## 技术决策

### Box2DSharp 引入方式

| 端 | 方式 | 说明 |
|----|------|------|
| 服务端 | NuGet `Box2DSharp` | 在 `Entity.csproj` 锁定具体版本 |
| Unity | 优先 NuGetForUnity；失败则源码引入 | 目标是双端同版本 |

### 测试场景设计原则

覆盖 Box2D 核心路径：
- 刚体动力学（重力、力、速度积分）
- 碰撞检测（AABB + 窄相）
- 碰撞响应（弹性、摩擦）
- 多体交互（堆叠、链式碰撞）

### 稳定排序与哈希策略（必须）

- 每个 Body 在创建时分配稳定 `DeterminismId`（`long` 递增）。
- 快照时按 `DeterminismId` 排序，而不是依赖 `World` 内部链表顺序。
- 哈希输入字段：
  - `DeterminismId`
  - `Position.X/Y`
  - `Angle`
  - `LinearVelocity.X/Y`
  - `AngularVelocity`
  - `IsAwake`
- `float` 统一转为 `BitConverter.SingleToInt32Bits()` 后参与比较与哈希。

## 实现步骤

### Step 1：接入依赖并验证最小运行

- `Entity.csproj` 增加 Box2DSharp PackageReference（固定版本）。
- Unity 端完成可编译接入。
- 最小验证：创建 `World` 并执行 `Step()` 不报错。

### Step 2：实现共享测试场景 `DeterminismTestScenario`

场景（固定参数、无随机）：
1. 静态地面（EdgeShape）。
2. 5 个动态圆形自由落体。
3. 3 个动态矩形带初速度碰撞。
4. 1 个动态圆形持续施力。

仿真参数：
- gravity=(0, -10)
- dt=1.0f/30
- velocityIterations=8
- positionIterations=3
- totalSteps=300

### Step 3：实现快照与差异定位 `PhysicsWorldSnapshot`

核心接口：
- `CaptureWorldSnapshot(World world)`
- `ComputeSnapshotHash(snapshot)`（SHA256）
- `CompareSnapshots(expected, actual)`（返回首个差异）

首个差异至少包含：
- `FrameIndex`
- `DeterminismId`
- `FieldName`
- `ExpectedBits`
- `ActualBits`
- `ExpectedValue`
- `ActualValue`

### Step 4：服务端确定性测试入口

流程：
1. 同配置运行 10 次仿真。
2. 每帧记录哈希（300 帧）。
3. 与基准运行逐帧比较。
4. 输出结果：是否 100% bit-exact。

附加：
- `net8.0` 与 `net9.0` 分别执行并记录。
- 导出哈希序列文件与首帧分歧信息（如有）。

### Step 5：Unity 单平台确定性测试

EditMode：
- 与服务端同场景同参数跑 10 次。
- 比较逐帧哈希，要求 100% 一致。

IL2CPP（明确流程）：
1. 构建测试 Player（Development Build）。
2. Player 启动后自动执行 10x300 测试。
3. 输出哈希序列到文件。
4. 与 Mono/EditMode 基线自动对比并生成差异摘要。

### Step 5.5：跨平台信息性对比

- 服务端（net8.0）哈希序列 vs Unity（Mono/IL2CPP）哈希序列。
- 记录：
  - 首次分歧帧号
  - 300 帧结束时最大位置偏差
  - 平均位置偏差

说明：
- 跨平台不一致不阻塞本阶段通过，但必须写入报告。

### Step 6：验证报告输出

报告必须包含：
1. 完整环境锁定信息。
2. Box2DSharp 版本与接入方式。
3. 场景与参数。
4. 单平台确定性结果（通过/失败）。
5. 跨平台差异与首帧分歧详情。
6. 性能基线（300 步耗时）。
7. 对 v0.3 回滚频率的定量建议。

## 差异判定与指标

### 单平台（硬性）

- 服务端：10 次 * 300 帧哈希全一致 -> 通过。
- Unity Mono：10 次 * 300 帧哈希全一致 -> 通过。
- Unity IL2CPP：10 次 * 300 帧哈希全一致 -> 通过。

### 跨平台（信息性）

固定记录以下指标：
- 首帧分歧 `firstDivergenceFrame`。
- 10 秒末最大位置偏差 `maxPositionDelta`。
- 10 秒平均位置偏差 `avgPositionDelta`。

建议阈值（用于风险分级，不作为阻塞）：
- 低风险：`maxPositionDelta < 0.001`
- 中风险：`0.001 <= maxPositionDelta < 0.01`
- 高风险：`maxPositionDelta >= 0.01`

## 关键风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Unity 端 NuGet 不可用 | 无法统一依赖 | 退回源码接入，保持双端源码版本一致 |
| 同平台复跑不一致 | 确定性前提失效 | 排查多线程、容器遍历顺序、未初始化数据、时间依赖 |
| net8 与 net9 不一致 | 升级后行为漂移 | 锁定运行时；CI 加确定性回归 |
| 跨平台偏差过大 | 回滚频率上升 | 评估定点数方案或提高服务端修正策略 |
