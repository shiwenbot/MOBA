# 羽毛球核心玩法 — 阶段总目录

## Context

基于已有的游戏设计文档（击球系统、势系统、模糊起手等 GDD），将核心玩法拆解为可独立验证的工程阶段。每个阶段聚焦一个核心问题，产出可运行、可体验的增量。

本文档只定义阶段目标、阶段边界和每个阶段对应的计划文档。具体实现步骤见各阶段计划。

### 已锁定的设计决策

1. **设计支柱**：读招即玩法、每一拍都有意义、手机上也能精妙操作、30 秒内让你爽一次。
2. **击球系统**：方向输入 + 单击球键，6 种球路（高远球/吊球/扣杀/平抽/网前球/挑球），时机判定（Perfect/Good/Late/Miss）。
3. **势系统**：0~100 势头条，击球品质三元组驱动势头变化，崩溃触发终结窗口。
4. **模糊起手**：引拍阶段球路不明确，渐进揭示。
5. **羽毛球物理**：高空气阻力弹道模型，水平速度指数衰减约 60%/s。

### 设计原则

1. **每阶段可独立验证**：完成标准必须包含可运行的 demo，不是"代码写完"而是"能玩到"。
2. **阶段聚焦**：每个子阶段只解决 1 个核心问题。
3. **先骨架后血肉**：先跑通核心循环（打球→对打→计分），再做系统深度（势、模糊起手、AI）。
4. **参考源码但不照搬**：Pure Badminton 反编译代码作为物理参数和实现思路参考，不是移植目标。

## 阶段推进规则

1. 每个阶段文档必须包含：目标、范围、非目标、技术决策、实现步骤、文件结构、完成标准。
2. 当前阶段完成标准全部满足后，才能进入下一阶段。
3. 阶段结束时同步更新本总目录中的状态标记。
4. **可玩性验证是每个阶段的必修项**——必须有可运行的 demo，不能只是"代码编译通过"。
5. 参考源码用于获取物理参数和实现思路，不用于照搬代码。
