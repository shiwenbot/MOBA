# 弹珠技术演示-阶段总目录

## Context

当前分支 `feature/pinball-tech-demo` 的目标是把项目收敛为一个弹珠玩法技术展示。它不追求完整商业游戏内容，重点展示状态帧同步、确定性物理、客户端预测、服务端权威、快照回滚和调试观测能力。

## 当前基线

- TEngine / HybridCLR / YooAsset 底座保留。
- Fantasy 网络链路保留。
- Battle Scene、30Hz Tick、输入上行、服务端权威快照、客户端预测回滚保留。
- Box2D / Box2DSharp 物理底座保留。
- Buff / SkillGraph 等战斗系统暂时不是弹珠演示主线，后续只在确实能服务展示时再接入。
- 旧玩法原型已从本分支删除，后续文档和代码不得继续新增旧方向引用。

## 技术展示目标

1. **物理可视化**：弹珠、边界、障碍、目标物在固定 Tick 下稳定运行。
2. **同步可验证**：同一输入在服务端和客户端预测中产生可对比状态。
3. **回滚可观察**：出现权威快照差异时，能够展示回滚帧、重播范围和修正结果。
4. **网络可调试**：可展示 RTT、服务器帧、客户端帧、预测领先量、输入缓冲和快照延迟。
5. **场景可演示**：打开 Battle 演示即可看到弹珠发射、碰撞、得分或触发目标。

## 非目标

- 不恢复旧 MOBA 或旧玩法原型。
- 不先做复杂关卡编辑器。
- 不优先接入角色动作、技能表现或商业化 UI。
- 不把技术演示扩展成完整玩法前，先保证同步链路可解释、可验证。

## 推荐开发顺序

1. 先在 `GameShared/FrameSync` 下定义弹珠状态和纯逻辑 Step。
2. 再接入 `BattleLogic` 服务端权威推进。
3. 然后扩展 `S2C_FrameSnapshot` 或新增子结构，把弹珠状态进入快照。
4. 最后做 Unity 表现层和调试 UI。
