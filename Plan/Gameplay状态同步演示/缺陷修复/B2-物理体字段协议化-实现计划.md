# B2：物理体四字段协议化

**性质**：🟡 隐患（当前恰好能对上，将来必崩）
**优先级**：B1 之后
**日期**：2026-08-05
**状态**：已完成；自动化验收见 `Tools/AutomationAcceptance/物理体字段协议化-验收测试指南-20260805.md`

## 1. 缺陷描述

`RotationRadians / AngularVelocity / IsAwake / IsEnabled` 四个字段**协议里不存在**。客户端 `BattleClientController.cs:673-682` 构造 `PhysicsBodySnapshot` 时写死：

```
Rotation        → Fixed64.Zero
AngularVelocity → Fixed64.Zero
IsAwake         → true
IsEnabled       → true
```

而服务端哈希的是 `_physicsWorld.TakeSnapshot()` 的**真实 body 状态**，`StateHasher.cs:67-91` 把六个 raw 值和两个 bool 全部混入。

### 1.1 为什么现在没炸

纯靠服务端恰好满足四条不变量：

| 字段 | 服务端现状 |
|---|---|
| `RotationRadians` | 仅 `FixedPhysicsBody.cs:11` 构造置零，全代码库无写入点 |
| `AngularVelocity` | `FrameSyncPhysicsWorld.cs:112` 每帧 Step 强制归零 |
| `IsAwake` | 构造置 true（`:15`），`FrameSyncPhysicsWorld.cs:115` 只会再置 true，**无置 false 路径** |
| `IsEnabled` | 构造置 true（`:16`），无写入点 |

body 集合也恰好一对一：`EnsureBody` 的全部调用点传的都是 playerId，`RemovePlayer`（`BattleLogic.cs:74-84`）同步调 `RemoveBody`。

### 1.2 破坏后的后果

任一条不变量被破坏 —— 加角色朝向、睡眠优化、昏迷/定身技能、投射物 body、静态墙 —— 后果是双重的：

1. **每客户端每次上报全部失配**，`HashMismatchCount` 线性增长
2. **客户端物理世界是真的错**，回滚重放会从错误基准出发

而且告警会把人往 `StateHasher` 上带，实际该改的是 proto。这是典型的隐式契约：能跑，但没人守着，破坏时的错误信息指向错误的位置。同类问题见 [`../设计教训-两类静默失效.md`](../设计教训-两类静默失效.md)。

## 2. 修法

### 2.1 改 proto

`PlayerSnapshot`（`OuterMessage.proto:101-127`）现有三个占位字段：

```
uint32 ReservedField8  = 8;
uint32 ReservedField9  = 9;
uint32 ReservedField10 = 10;
```

改为：

| 字段号 | 新定义 | 说明 |
|---|---|---|
| 8 | `int64 AngularVelocityRaw` | Fixed64 raw 值 |
| 9 | `bool IsAsleep` | **取反语义**，见 2.2 |
| 10 | `bool IsDisabled` | **取反语义**，见 2.2 |
| 23 | `int64 RotationRadiansRaw` | 新增字段号 |

改完跑 `GameServer/Tools/ProtocolExportTool/Run.bat` 一次导出两端。

> 字段 8 从 `uint32` 改 `int64` 不是 wire type 兼容改动（varint 位宽不同），但**本项目无所谓** —— 两端同一次生成同一次编译，不存在版本错配。详见 `00-总览与执行顺序.md` 的「已作废的顾虑」。

### 2.2 布尔取反的理由：带宽

protobuf 对默认值不落字节。若直接用 `IsAwake` / `IsEnabled`，常态是 `true`（非默认值），**每玩家每帧都要上线约 4 字节**，把 S2 脏同步省下的带宽吐回去。

存 `IsAsleep` / `IsDisabled`，常态 `false` = 默认值 = **不落字节**。一行取反换回全部带宽。

`RotationRadiansRaw` 和 `AngularVelocityRaw` 常态为 0，本来就不落字节，不需要处理。

**这个决策与兼容性无关**，纯粹是带宽。早期讨论里把它和版本兼容混在一起，已作废。

### 2.3 服务端填字段

`BattleComponent.cs:207-227` 构造 `PlayerSnapshot` 处，从已有的 `bodySnapshot` 取值（`:186` 已经拿到了 `hasPhysics` 和 `bodySnapshot`，无需额外查询）：

- `AngularVelocityRaw` / `RotationRadiansRaw` 取 raw 值，`hasPhysics == false` 时填 0（与现有 `LinearVelocityXRaw` 的处理一致，见 `:213-214`）
- `IsAsleep = !bodySnapshot.IsAwake`、`IsDisabled = !bodySnapshot.IsEnabled`，`hasPhysics == false` 时填 `false`

### 2.4 客户端读字段

`BattleClientController.cs:673-682` 删掉四个写死常量，改为：

- `Fixed64.FromRaw(player.RotationRadiansRaw)` / `Fixed64.FromRaw(player.AngularVelocityRaw)`
- `IsAwake = !player.IsAsleep`、`IsEnabled = !player.IsDisabled`

[`../S3-哈希上报与服务端告警-实现计划.md`](../S3-哈希上报与服务端告警-实现计划.md) 里关于「死字段」的论述要同步更新。

## 3. 验收判据（这里有陷阱）

### 3.1 为什么不能靠观测哈希

**修完哈希值一个都不会变。** 服务端当前这四个值恰好等于客户端写死的值，所以修复前后哈希完全相同，弱网测试观测不到任何差异。

这类「消除隐式契约」的改动，**观测正常运行的行为无法验证它**。若验收指南只写「跑弱网测试看 mismatch」，验收 agent 会无从下手或误判「无法验证」。

### 3.2 也不能只做 DTO round-trip

单纯验证 `PlayerSnapshot` 序列化前后四个字段相等，盖不住这些错误：

- 服务端忘记从 `bodySnapshot` 赋值（字段留默认值）
- 客户端忘记取反（`IsAwake = player.IsAsleep`）
- 客户端字段映射错位（Rotation 读到 AngularVelocity）
- `ConvertSnapshot` 里残留部分常量（改了两个漏了两个）

这些都是**接线错误**，DTO 层测不出来。

### 3.3 正确判据：端到端非常态值

构造一个**四个字段全部为非常态值**的 physics body，例如：负角速度、非零旋转、`IsAwake = false`、`IsEnabled = false`，然后走完整通路：

```
服务端 PhysicsBodySnapshot（四字段非常态）
  → BattleComponent 构造 PlayerSnapshot
  → protobuf serialize / deserialize
  → 客户端 ConvertSnapshot
  → PhysicsBodySnapshot
  → StateHasher.Hash
```

**判据**：末端 `PhysicsBodySnapshot` 与源头逐字段相等，且两侧 `StateHasher.Hash` 相等。

用非常态值是关键 —— 常态值下写死的代码也能通过测试，等于没测。

### 3.4 辅助的静态检查

代码检查 `BattleClientController.cs:673-682` 不再出现 `Fixed64.Zero` / `true` 字面量。这条作为端到端测试的补充，不能单独作为判据。

## 5. 可选的加固

改完之后，`StateHasher` 混入的字段与协议传输的字段就一一对应了。可以考虑在 `FixedPhysicsBody` 上加注释说明「本结构的每个字段都必须能通过 `PlayerSnapshot` 往返，新增字段时同步改 proto」，把隐式契约变成显式约定。

另一个可选项：客户端 contacts 目前不重排（`BattleClientController.cs:694-699`），而 players 和 bodies 都防御性排了（`:691-692`）。现在靠服务端 `FrameSyncPhysicsWorld.cs:164` 排好，能对上。这个不对称本身不是 bug，但顺手加一行 `Array.Sort` 可以消除对服务端排序的隐式依赖。**不强制，属于同类隐式契约。**
