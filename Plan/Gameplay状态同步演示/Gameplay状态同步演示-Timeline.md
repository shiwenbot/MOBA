# Gameplay 状态同步演示 Timeline

## Context

> **本文档的 P 编号是阶段划分，不是执行顺序。**
> 执行顺序统一走 **S1~S10 单轴编号**，见 [00-总索引.md](00-总索引.md) 的「S 编号总表」。
> 每个 P 阶段下方已标注对应 S 号。当前下一项是 **S1**（预测误差平滑，原 P4a），排在 S6（原 P2）之前。

本分支面向 Gameplay 岗求职展示，不再以“弹珠技术演示”或“完整技能系统”为主线。当前目标是制作一个极简俯视角 Gameplay 状态同步沙盒：用小球角色、小房间、Dash、体力、Recover 和撞击击退，展示弱网条件下的按帧输入、客户端预测、服务端权威校验、不一致诊断与回滚重播。

本 demo 的价值不在于美术复杂度，而在于面试官能清晰看见：

1. 输入如何绑定到 `FrameIndex`。
2. 客户端预测了哪些 Gameplay 状态。
3. 服务端如何在同一帧语义下消费命令并下发权威快照。
4. 客户端如何对比差异、回滚到权威帧并重播到当前预测帧。
5. 弱网下系统如何保持操作手感和最终状态一致。

## 产品定位

- **目标受众**：Gameplay / Unity 战斗 / 网络同步相关岗位面试官。
- **展示形态**：本地 client/server + 弱网工具；优先可解释，不优先公网部署。
- **场景形态**：俯视角小房间 + 小球角色 + 目标区 + 调试可视化。
- **核心卖点**：Gameplay 状态帧语义、预测、权威修正、rollback replay 和诊断能力。

## 非目标

- 不实现完整技能系统。
- 不实现复杂 Buff、伤害、命中、目标选择或战斗结算。
- 不追求完整商业玩法循环。
- 不优先接入复杂动画、角色模型或大量美术资源。
- 不把不可控 Unity 物理结果作为核心一致性来源。

## 技术约束

1. 所有客户端可预测状态变化都必须是按帧命令，命令携带 `FrameIndex`。
2. 客户端预测和服务端权威必须共享同一全局逻辑帧语义。
3. 进入预测链路的状态必须纳入快照、哈希、一致性检查、历史缓存和回滚重播。
4. 不适合预测的结果走服务端权威快照，不能伪装成预测命令。
5. mismatch 日志必须打印真实差异域，例如位置、速度、体力、状态机、击退状态。

### P2：Dash / 体力 / Recover / 撞击击退

- **执行编号**：**S6**
- **状态**：未开始
- **范围调整记录（2026-08-03）**：本阶段范围已由「Dash + 体力 + Recover」扩为「**+ 撞击击退**」，依据见 `物理层与玩法形态-讨论记录-20260803.md` 决策 1。击退的定位是**服务端权威、客户端故意不预测**，用来说清「什么该预测、什么不该」，与 Source 系通行做法一致（该记录 §4）。
- **目标**：让 demo 从“同步 Transform”升级为“同步 Gameplay 行为状态”，并给出一个明确标注「故意不预测」的对照项。
- **范围**：
  - Shift Dash 输入，作为 `PredictableAction`，不命名为技能。
  - Dash 消耗体力。
  - Dash 后进入 Recover 状态，Recover 期间禁止再次 Dash。
  - 体力恢复按逻辑帧推进。
  - 体力、Dash 状态、Recover 剩余帧进入快照、哈希、diff 和回滚。
  - **撞击击退**：两球相撞时产生一次瞬时冲量，由服务端权威裁决，客户端不预测，误差由 S1 的平滑层吸收。
- **非目标**：
  - 不做 SkillGraph。
  - 不做技能表现资源。
  - 不做伤害、命中或 Buff。
  - 不预测击退（这是刻意选择，不是缺陷）。
- **验证方式**：
  - 客户端在输入帧预测 Dash 和体力消耗。
  - 服务端在同一 `FrameIndex` 执行 Dash。
  - 故意制造错帧扣体力时，mismatch 能打印体力和状态机差异。
  - 两客户端对撞后，两端位置最终收敛到服务端裁决结果。
- **完成标准**：
  - Dash 手感在弱网下不等待服务端确认。
  - 回滚后位置、体力、状态机一致。
  - 日志能明确区分 `PositionMismatch`、`StaminaMismatch`、`StateMismatch`。
  - 击退产生的位置修正走 S1 平滑层，不出现硬跳。
- **前置依赖**：**S1** 必须先完成。击退是本平滑层要吸收的最大一类误差，没有平滑层时击退演示不成立。
- **反向约束**：击退定稿后须回头复核 S1 的大误差阈值 `6.0`，**阈值必须大于单次最大击退距离**，否则击退会走硬跳分支。

## 面试讲解主线

1. 为什么选择极简俯视小球：降低表现噪声，突出 Gameplay 状态同步。
2. 哪些状态允许预测：移动、Dash、体力消耗、Recover。
3. 哪些状态保持权威：撞击击退结果、最终位置校正。为什么击退故意不预测——对手位置在本地是过去时，预测它的期望值是负的（详见 `物理层与玩法形态-讨论记录-20260803.md` §4.6）。
4. 如何避免伪 mismatch：客户端和服务端共享同一 `FrameIndex` 语义。
5. 如何定位问题：状态 hash + 字段级 diff + rollback 可视化。
6. 如何扩展到技能：Dash 已经是 `PredictableAction` 模型，后续可扩展为技能输入，但当前 demo 不把完整技能系统作为范围。
