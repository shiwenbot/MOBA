## 1. 目的

验证四件事：

1. 业务代码与手工维护的服务端项目已移除 `Box2DSharp` 依赖，反射 hack 已清除。
2. 物理行为**等价**——卡位、边界、分离表现与改动前一致。
3. 确定性**未退化**，且同一次运行内仍 bit-exact。
4. 逻辑层现在**完全定点**，跨端可复现。

## 2. 边界

本次**不**验收：撞击击退玩法（属 S6）、远端插值（S9）、`GameplayRoomSettings` 的 float 量化改造（明确留到独立改动）。`Box2DSharp.dll` 本体按回退策略保留到 Unity/真机验收完成；因此 Unity 自动生成的仓库根目录 `.csproj` 仍可能列出它，不手改也不纳入本阶段静态检查。

## 2.5 最重要的一条：哈希基线**会变**，这是预期

**不要把哈希变化判为 FAIL。**

改动前基线是 `hash=0xA565C15299DDC667`，那是「Box2D + `Fixed64→float→Fixed64` 往返 + `MathF.Sqrt`」下的值。S2 去掉了 float 往返、把三处开方换成 `FixedMath.Sqrt`，**数值结果必然不同**。当前已验收的新基线为 `hash=0xD01E17BC0F96A3EB`（2026-08-03，连续 3 次无头运行一致）。

正确的判定方式是：

| 检查 | 期望 |
|------|------|
| 哈希与旧基线相同 | ❌ **反而可疑** —— 说明 float 路径可能没真正去掉 |
| 哈希变了，但同一次运行内 10×300 帧**互相一致** | ✅ 正确 |
| 哈希在多次独立运行间**可复现** | ✅ 正确，这是本阶段的核心收益 |

**验收记录**：新哈希已回填为 `0xD01E17BC0F96A3EB`，同步记录在本指南、S2 实现计划和 S1 验收指南。

## 6. 失败排查顺序

1. **`Box2DSharp` 在静态检查范围内仍有命中**
   → 分实现漏改和手工维护 csproj 漏改。`FrameSyncPhysicsWorld.cs` 曾是唯一 `.cs` 引用点；csproj 有三处：`Entity.csproj`、`Main.csproj`、`FrameSyncMvpAValidator.csproj`。Unity 侧 `Assembly-CSharp.csproj` 是自动生成的；在 DLL 保留期间可能仍有引用，最终删除 DLL 后会自动更新，不用手改。

2. **编译报「找不到类型」**
   → 与 S1 不同，**S2 的新文件在 `GameShared/` 下是通配符链接**（`Entity.csproj:31`），自动纳入，不需要手动加 `Compile Include`。若仍报错，检查是否误把文件放进了 `GameLogic/`（那里是逐文件列举）或 `Tests/`（被 Exclude）。

3. **`Scenario 3 PlayerCollision` 的 `minSeparation` 不是 `0.9000`**
   → occupancy 分离算法在类型转换中出错。重点看 `ResolvePlayerOccupancy` 的三处开方是否都换成了 `FixedMath.Sqrt`，以及 `CalculateSeparationShares` 的比例分配是否仍用同一套 penetration 语义。

4. **`stationaryDisp` 不是 `0.0000`**
   → 静止玩家被推动了。看 `CalculateSeparationShares` 的「谁在推」判定（`MovementIntentEpsilon` 比较）是否在定点化时改变了语义。原逻辑：只有 `towardIntent > epsilon` 的一方才承担位移。

5. **哈希三次运行不一致**
   → **这是最严重的失败**，说明引入了新的非确定性源。查：是否有 `Dictionary` 遍历序未排序、是否残留 `float` 运算、是否用了 `MathF`。`BuildSortedBodyBuffer()` 必须保留。

6. **`room-boundary-clamps-player` FAIL**
   → **大概率属预期**。该用例（`BattlePredictionSelfTestSuite.cs:124-133`）断言具体 `m_rawValue`，去掉 float 往返后期望值会变。正确处理是**重新取实测值更新用例**，不是改代码去凑旧值。但要先确认新值合理（应约等于 `PlayerMaxX`）。

7. **`authoritative-snapshot-restores-physics-world` FAIL**
   → 这条断言的是相对关系（恢复前后一致），**不该因数值变化而失败**。若 FAIL，说明 `RestoreSnapshot` 的简化写错了 —— 检查是否漏恢复某个字段（`IsAwake` / `IsEnabled` / 角速度）。

8. **`physics-roundtrip` 或 `physics-affects-hash` FAIL**
   → 这两条**不在** `BattlePredictionSelfTestSuite.cs`，而在 `GameShared/FrameSync/Snapshot/SnapshotSelfTestSuite.cs`（`:17-18`），用的是 `TestPhysicsSnapshotProvider` 假 provider，**本不该受物理重写影响**。若 FAIL，说明动了 `PhysicsWorldSnapshot` / `PhysicsBodySnapshot` 的结构语义而非仅删 float 构造器。

9. **边界表现抖动 / 贴墙震荡**
   → `ClampPlayersToRoom` 的速度归零条件。原逻辑只在「已到边界且速度指向边界外」时归零该轴速度，定点化时容易把条件写成无条件归零。

10. **报 `NETSDK1045`**
    → 用了系统 dotnet。改用 `C:/Users/shiwe/.dotnet/dotnet.exe` 全路径。

11. **报 `MSB3027` / `MSB3021`**
    → 服务端正在运行锁住 dll。停掉进程，或只跑 4.2 的 `build Entity.csproj`。

12. **`GameplayRoomSettings` 被改动**
    → 本阶段明确不动它。若 diff 里有，需问清原因 —— 改了会让边界用例的变化与物理重写效果混淆，无法归因。
