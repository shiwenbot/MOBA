## 1. 验收目标

本指南同时验证四条链路：

1. Dash、体力和 Recover 由客户端预测，输入、执行态和恢复计数可回滚重放。
2. 击退只由服务端碰撞裁决；客户端收到触发状态后继续逐帧演化，不自行触发新击退。
3. 远端玩家不进入本地 `_worldState` 或回滚，但以 kinematic 只读 body 参与占位分离。
4. 新增状态完整进入 proto、哈希、diff、快照与自动化报告，弱网下失配次数有界。

## 6. 双客户端弱网场景

```powershell
powershell -ExecutionPolicy Bypass -File .\Tools\AutomationAcceptance\Run-BattleAcceptance.ps1 `
  -Scenario two-client-knockback -Bridge puerts -InteractiveEditor
```

场景固定为双向各 100ms 延迟、零抖动、零丢包、固定 seed。客户端 A 在全局阶段 30/150 Dash，客户端 B 在 90/150 Dash，阶段 150 为双方同时 Dash；场景在 240 帧后收集报告。

脚本必须对两个客户端分别满足：

| 报告字段 | 判据 |
|---|---|
| `networkUplinkDelayMs` / `networkDownlinkDelayMs` | 都等于 100 |
| jitter / loss 四项 | 都等于 0 |
| `activePlayerCount` | 至少 2，且 playerId 不重复 |
| `dashCount` | `>= 2` |
| `knockbackTriggerCount` | `> 0`，防止碰撞失效后假通过 |
| `stateMismatchCount` | `<= 3` |
| `contactMismatchFrames` | `<= 6` |
| `positionMismatchCount` / `staminaMismatchCount` | 单独上报，不与 state mismatch 混计 |
| `staminaAtEnd` | 在 `[0, maxStamina]` 内，两个客户端最终可解释 |

若保留了决策五实施前的同参数报告，还必须验证 `contactMismatchFrames` 下降至少 60%。没有可比的旧报告时，不伪造相对数据，以绝对阈值和四条远端镜像用例作为当前机械门禁。

报告位于 `_codex_tmp\battle-automation\<timestamp>`。验收记录应保留两个客户端的 report、服务端日志、网络配置和 seed。

## 7. 画面与交互

Play Mode 至少检查一次本地 Dash、被击退和双方 Dash 对撞：

- 按 Shift 后同一输入周期立即 Dash，不等待服务器确认；长按不会在 Recover 结束后自动连发。
- Dash 期间球体颜色与 Trail 明显变化，结束后恢复；Trail 不应遮挡球体或永久残留。
- 世界空间体力条起手时扣除、随后按整数节律恢复；条宽稳定，不随数值改变布局。
- Recover 期间再次按 Shift 不扣体力、不重置 Dash。
- 被击退时有清晰强调，权威 Ghost 与预测位置分离时连线可见，收敛后消失。
- HUD 能同时读到 Dash 阶段、体力和击退剩余帧，文本不重叠、不超出面板。

## 8. 失败排查

1. Dash 不起手：查 `InputBuffer` 的按下边沿、SkillId 是否写入 `_inputHistory`，以及体力/Recover/活跃执行三条入口守卫。
2. 回滚后 Dash 丢失或串技能：查 `ActiveSkillExecutionSnapshot` 的 CasterId、TargetId、SkillId 和有序 blackboard/Delay 序列。
3. 击退每帧重置：查新接触集合与 `(contactPair, dashEpoch)` 边沿；不能按“当前正在接触”触发。
4. 接触期间持续位置失配：查远端 kinematic body 是否在 `RestoreSelfOnly` 之后重建、每次权威快照是否更新 transform。
5. 击退首帧速度偏小：检查顺序必须是 Apply 位移后再 Decay，不能在积分前衰减。
6. 体力回滚后变零：查 Numeric 的 BaseStamina/BaseMaxStamina proto 字段和 `StaminaRegenCounterFrames` 恢复。
7. 报告显示一个玩家：检查 `CaptureAutomationSnapshot` 是否同时合并 self world state 与 `RemotePlayerBuffer`，并按 playerId 去重。
8. 两端哈希不一致：先查新字段映射与集合排序，不要直接更新基线。
