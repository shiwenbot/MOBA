## 1. 目的

本指南用于让其他 agent 在当前仓库中运行 **真实 Unity Editor 客户端 + battle server** 的 Buff 验收测试。

这次新增的验收场景是：

- `two-client-buff-lifecycle`
- `two-client-skill-buff`

它验证的是：

1. 两个真实客户端都能成功加入战斗
2. 服务端会在场景脚本中自动注入一个权威 Buff
3. 两个客户端都能从权威快照里观察到该 Buff 出现
4. Buff 倒计时结束后，两个客户端都能观察到该 Buff 消失

这条验收链路重点覆盖：

- `S2C_FrameSnapshot` 中的 Buff 广播
- 客户端 `BattleClientController` 对 Buff 快照的还原
- 真实客户端自动化快照中的 Buff 可观测性
- Buff 生命周期在真实双端联调中的表现

## 2. 本次场景的边界

这个验收场景当前验证的是 **Buff 状态生命周期**，不是完整的数值效果系统。

也就是说，它能证明：

- Buff 状态被服务端正确注入
- Buff 状态能被客户端收到并还原
- Buff 状态会在客户端真实运行时出现和消失

但它 **不直接验证**：

- Buff 对 `Attack/Health/Mana` 的数值修饰是否符合策划规则
- 技能图节点是否正确触发 Buff
- Luban Buff 配置表是否已经接通

数值层和回滚层目前仍主要由以下代码级自测兜底：

- `prediction-self`
- `snapshot-self`
- `buff-roundtrip`
- `skill-trigger-buff`
- `skill-buff-roundtrip`
- `authoritative-snapshot-restores-player-buffs`

## 5. 环境策略

这条脚本现在按“每次测试前清理旧环境”的思路运行：

1. 会杀掉旧的 `battle server`（监听 `20101` 端口）

3. 会为本次运行创建新的 `_codex_tmp\battle-automation\<timestamp>` 输出目录

因此 **不需要** 先手工复用旧 server，也 **不建议** 先自己起一个 battle server 再跑。

## 8. 失败时优先看什么

按这个顺序排查：

1. `combined-report.json`
   看两个客户端的 `passed`、`reason`

2. `client-a-report.json` / `client-b-report.json`
   重点看：
   - `snapshot.activePlayerCount`
   - `snapshot.totalActiveBuffCount`
   - `snapshot.players[*].activeBuffs`
   - `capturedLogs`

3. `client-a-events.log` / `client-b-events.log`
   看是否正常进入：
   - join
   - observe buff appear
   - observe buff expire

4. `server.log`
   看 battle server 是否真正注入了 Buff

5. `client-a-unity.log` / `client-b-unity.log`
   看 Unity Editor 启动、连接、消息处理、异常信息

## 9. 常见失败类型

### 9.1 Unity Licensing / batchmode 问题

现象：

- Unity 退出码异常
- 日志里出现 LicensingClient

处理：

```powershell
powershell -ExecutionPolicy Bypass -File D:\unity\Tencent\TEngine\Tools\AutomationAcceptance\Run-BattleAcceptance.ps1 -Scenario 'two-client-buff-lifecycle' -InteractiveEditor
```

### 9.2 客户端加入失败

现象：

- `join-failed:*`

处理：

- 看 `server.err.log`
- 看 battle server 是否成功启动
- 看客户端是否成功连接 `20101`

### 9.3 Buff 一直没有出现

现象：

- `reason = buff-never-appeared buffId=9001`

处理：

- 先看 `server.log` 是否打印了 `Queued buff lifecycle commands`
- 再看客户端快照里的 `players[*].activeBuffs`
- 若 server 已注入但客户端没有，重点查协议广播或客户端快照转换

### 9.4 Buff 出现了但没有消失

现象：

- `reason = buff-never-expired buffId=9001`

处理：

- 检查 `RemainingFrames` 是否递减
- 检查 `BuffSystem.ApplyTick()` 是否在真实 Tick 中运行
- 检查客户端最终快照里的 `activeBuffs`
