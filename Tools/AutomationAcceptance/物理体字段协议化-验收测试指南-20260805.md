# 物理体字段协议化（B2）验收测试指南

对应实现计划：`Plan/Gameplay状态同步演示/缺陷修复/B2-物理体字段协议化-实现计划.md`。

## 1. 验收目标

验证 `RotationRadians`、`AngularVelocity`、`IsAwake`、`IsEnabled` 不再由客户端常量编造，而是从服务端 `PhysicsBodySnapshot` 经 protobuf 完整下发并在客户端还原。

协议映射如下：

| 字段号 | Wire 字段 | 客户端状态 |
|---|---|---|
| 8 | `int64 AngularVelocityRaw` | `Fixed64.FromRaw(...)` |
| 9 | `bool IsAsleep` | `IsAwake = !IsAsleep` |
| 10 | `bool IsDisabled` | `IsEnabled = !IsDisabled` |
| 23 | `int64 RotationRadiansRaw` | `Fixed64.FromRaw(...)` |

布尔字段采用反向语义是为了让正常状态 `IsAwake=true`、`IsEnabled=true` 在 wire 上保持 protobuf 默认值 `false`，避免常态每玩家每帧额外落字节。

## 2. 判据边界

服务端当前正常运行时这四个字段恰好一直是旋转 0、角速度 0、awake、enabled。因此本修复前后的正常场景哈希值不会变化，这是正确结果，不应更新既有哈希基线。

弱网观测也不能验证 B2：丢包只改变消息可见时机，无法让服务端产生四个非常态值。验收必须依赖 `physics-protocol-roundtrip-preserves-nondefault-fields` 这条端到端协议测试，不能用“弱网下没有 mismatch”代替。

该测试固定使用：

- 非零旋转 `345678901` raw；
- 负角速度 `-678901234` raw；
- `IsAwake = false`，wire 上必须为 `IsAsleep = true`；
- `IsEnabled = false`，wire 上必须为 `IsDisabled = true`。

## 4. 端到端测试必须覆盖的路径

```text
服务端 PhysicsBodySnapshot（四字段非常态）
  -> BattleSnapshotProtocolMapper.WritePhysicsBody
  -> S2C_FrameSnapshot protobuf serialize / deserialize
  -> BattleSnapshotProtocolMapper.ReadPhysicsBody
  -> 客户端 PhysicsBodySnapshot
  -> StateHasher.Hash
```

末端 body 必须与源 body 九个字段逐值相等，源世界和解码世界的哈希也必须相等。只测 DTO 序列化不够，因为它抓不到服务端漏赋值、客户端漏取反、Rotation/AngularVelocity 接反或残留常量。

## 6. 失败排查

1. 非零 raw 值往返变 0：先检查 proto 与两份生成文件是否同批更新，再查 `WritePhysicsBody` 是否从真实 `bodySnapshot` 取值。
2. 布尔值相反：检查 wire 语义是否被误当成 `IsAwake` / `IsEnabled` 直接赋值。
3. body 逐字段相等但哈希不等：检查测试构造的玩家、contacts 和帧号是否两侧完全相同；本阶段不应修改 `StateHasher`。
4. 既有固定哈希变化：停止验收并检查是否改了世界态语义。B2 只补传输接线，正常值下不应改变任何既有哈希。
5. 单侧编译失败或字段缺失：重新执行协议导出，确认服务端与客户端生成文件都包含字段 8、9、10、23。
