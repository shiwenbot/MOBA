## 1. 目的

验证三件事：

1. 权威修正在渲染层平滑收敛，不再瞬移。
2. **平滑层未污染确定性**——逻辑状态与哈希逐位不变。这是最关键的一条。
3. 现有帧同步用例全部未被破坏。

## 5. 预期通过标准

### 无头

- 五条新用例退出码 `0`，输出 `PASS`。
- `--scenario=all` 输出 checks 与 scenarios **全部通过**，无 FAIL。
- `error-smoothing-matching-snapshots-decay`（S1 实施中追加的第五条）断言一致快照**不重设**误差基线。此条 FAIL 意味着 `CapturePredictionErrorAfterReconciliation()` 没被 `logRollback` 守卫住，每个到达的快照都会重启平滑计时器，偏移永不归零。
- `error-smoothing-does-not-affect-logic-state` 是硬性门槛：它断言对账重放完成后，自身逻辑位置的 `Fixed64.m_rawValue` 与权威快照值**逐位相等**，且同一时刻平滑偏移**非零**。此条 FAIL 意味着平滑层污染了仿真，**必须停止验收并退回实现**。
- `error-smoothing-overlapping-corrections-rebaseline` 覆盖的是常见路径而非边界：快照 30Hz 到达、平滑窗口 100~150ms，修正必然重叠。此条 FAIL 通常意味着偏移被写成了累加。

### 真机

- 单客户端正常移动时画面**无周期性抖动**。
- 触发回滚时（日志出现 `[Rollback]`）球**平滑靠拢**，不是瞬移。
- 无弱网时 ghost 与实心球基本重合。
- 弱网下 ghost 明显落后，修正时实心球平滑追上。
- 日志中 `[Consistency] MISMATCH` 的出现频率**不应因本次改动上升**。若上升，说明平滑量被误写回逻辑状态。

## 6. 失败排查顺序

按以下优先级看：

1. **编译报「找不到 PredictionErrorSmoother」**
   → `GameServer/Server/Entity/Entity.csproj` 第 29-33 行附近。该处是**逐文件显式链接** GameLogic 源码，不是通配符。新文件必须手动加 `Compile Include` 行。这是本方案最常见的失败原因。

2. **`error-smoothing-does-not-affect-logic-state` FAIL**

   先分清 FAIL 在哪一半，两半的成因完全不同：

   - **「逐位相等」那半失败** → 平滑偏移被写回了逻辑状态。查 `BattleSimulation.cs:415` `ReconcileAuthoritativeSnapshot`，偏移只能存在于渲染层，逻辑位置必须等于权威值。这是确定性事故，**必须退回实现**。
   - **「偏移非零」那半失败** → **大概率是采样点插错位置**，不是平滑器坏了。该函数有两个出口：`:439` 有一句 `if (!logRollback) return;`，而 `logRollback` 实参就是 `mismatch`（`:322`）。采样必须插在 `:437` 之后、`:439` 之前；插在函数真正的尾部（`:442` 后）会让采样在一致路径上永不执行。本用例推荐的构造模板 `AuthoritativeSnapshotRestoresPhysicsWorld()` 恰好走 `_skippedNoRecord` 分支（`mismatch=false`），必然命中提前返回。

3. **球平滑方向反了 / 先跳再回**
   → 误差采样时机。必须在**重放完成后**采集（`ReconcileAuthoritativeSnapshot` 尾部，`AdvancePredictionTo` 之后），不是应用快照的瞬间。

4. **球永远追不上 / 偏移越来越大 / 发散**
   → 偏移被写成了累加。应为「重设基准」：新偏移 = 上一帧实际绘制位置 − 新逻辑位置。快照 30Hz + 平滑窗口 100~150ms 意味着修正持续重叠，累加会滚雪球。`error-smoothing-overlapping-corrections-rebaseline` 应能复现。

5. **一直有残余偏移追不干净**
   → 平滑器衰减逻辑。检查是否精确归零而非渐近趋零；`error-smoothing-decays-to-zero` 应能复现。

6. **修正时出现二次跳变（先平滑一段又突然跳）**
   → 偏移被写成了直接覆盖，旧残余被瞬间抹掉。同第 4 条，应为重设基准。

7. **ghost 不显示 / 报找不到权威位置入口**
   → `BattleSimulation` 需要新增只读入口暴露「最近一次已应用权威快照中自身玩家的位置」。`_authoritativeSnapshots`（`:38`）是私有字段，原本没有对外读取入口。

8. **画面完全不动**
   → `BattleClientController` 的渲染写入。检查 transform 写入是否已搬到 `Update()`，以及偏移叠加是否写错目标。

9. **平滑看起来是一串小跳而不是连续滑动**
   → transform 写入还留在 `SyncRendering()` 里。它由 `Tick()` 调用，跑在 30Hz，必须搬到 `Update()`（渲染帧率）。同第 3 条的成因不同：这条是频率问题，第 3 条是方向问题。

10. **既有物理用例 FAIL**
    → 说明改动越界碰到了 `FrameSyncPhysicsWorld` 或快照结构。本方案不应触及这两处。

11. **报 `NETSDK1045: 当前 .NET SDK 不支持面向 .NET 9.0`**
    → 用了系统 `dotnet` 而不是 Rider 那套。改用 `C:/Users/shiwe/.dotnet/dotnet.exe` 全路径。加 `--framework net8.0` 或 `-p:TargetFramework=net8.0` 都救不了，别试。

12. **报 `MSB3027` / `MSB3021`：文件被 "Main (PID)" 锁定**
    → 服务端正在运行，锁住了 `Main/bin/Debug/net9.0/` 下的 dll。停掉服务端再跑。若只想验证编译，改用上面那条 `build Entity.csproj` 命令，它不受锁影响。

13. **新用例没报 FAIL 但也看不出跑没跑**
    → 大概率漏加 `BattlePredictionSelfTestSuite.cs` 的 `AllCaseNames` 数组（`:10-30`）。只加 `RunCase()` 分支的话，用例永远不会被调用，而 `--scenario=all` 照样报 PASS。这是静默跳过，务必核对数组里有那四个名字。
