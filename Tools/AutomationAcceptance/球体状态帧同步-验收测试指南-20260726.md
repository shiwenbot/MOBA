# 球体状态帧同步 验收测试指南

## 1. 目的与边界

本次改动是**表现层换形状 + 羽毛球代码归档**，没有触碰帧同步逻辑、网络协议、服务端仿真。

因此这份验收的性质是**回归验证**，不是新功能验证。要证明的是：

1. 归档羽毛球代码后，双端仍能正常编译
2. 玩家实体从 Capsule 换成 Sphere 后，状态帧同步链路完全不受影响
3. 两个真实客户端仍能加入房间、同步移动、正常断线

**不需要**新增验收场景。现有 `two-client-basic-move` 已经覆盖"双客户端同步移动"，正是球体演示依赖的链路。

### 本次改动清单

| 类型 | 内容 |
|------|------|
| 渲染 | `PrimitiveType.Capsule` → `Sphere`，命名 `BattleBall_{playerId}` |
| 渲染 | `localScale = 0.9`（对齐物理半径 0.45），`ToWorldPosition` 的 Y 由 `0.5f` 改为 `BallVisualRadius` |
| 重命名 | `_playerCapsules` → `_playerBalls`，`GetOrCreateCapsule` → `GetOrCreateBall` |
| 归档 | 羽毛球手写代码移至 `Archive/Badminton/` |
| 测试 | 删除 `FixedMathSharpTests.CourtBounds_EvaluatesFixedInputs`（依赖已归档的 `CourtConstants`） |

**逻辑层本来就是圆球**：`FrameSyncPhysicsWorld.cs` 中 `PlayerBodyRadius = 0.45`，物理体一直是 `CircleShape`。此前只是渲染用了胶囊体。

## 7. 失败排查顺序

考虑到本次改动的性质，按这个顺序查：

1. **`client-a-unity.log` / `client-b-unity.log`** —— 最可能的失败点
   本次归档了代码，优先确认是否有编译错误。重点搜：
   - `CourtConstants`
   - `GameShared.Badminton`
   - `ShuttlecockEntity`
   - `TbShuttlecockShot`
   - `CS0246`（找不到类型）

2. **`combined-report.json`** —— 看两个客户端的 `passed`、`reason`

3. **`client-*-report.json`** —— 重点看：
   - `snapshot.activePlayerCount`
   - `snapshot.players[*]` 的位置字段
   - `rollbackCount` / `lastRollbackReplayFrames`
   - `capturedLogs`

4. **`client-*-events.log`** —— 看是否正常 join 并产生移动事件

5. **`server.log` / `server.err.log`** —— 看 battle server 是否正常启动、接受输入

## 8. 常见失败类型

### 8.1 编译错误：找不到 CourtConstants / Badminton 类型

现象：Unity 日志出现 `CS0246`，提到 `CourtConstants` 或 `GameShared.Badminton`。

原因：还有代码引用了已归档的羽毛球类型。

处理：全仓搜索残留引用。已知并已处理的是 `FixedMathSharpTests.cs`。若出现新的，
把该引用一并清理，或从 `Archive/Badminton/` 取回对应文件。

### 8.2 编译错误：找不到 TbShuttlecockShot

现象：`Tables.cs` 报错找不到 `badminton.TbShuttlecockShot`。

原因：Luban 生成的配置代码被误删。这部分**故意保留在原地**，因为
`Tables.cs`（Luban 自动生成）硬引用了它们。

处理：确认以下路径仍存在：
- `UnityProject/Assets/GameScripts/HotFix/GameProto/GameConfig/badminton/`
- `GameServer/Server/Entity/Generate/GameConfig/badminton/`
- `UnityProject/Assets/AssetRaw/Configs/bytes/badminton_tbshuttlecockshot*.bytes`

### 8.3 Unity Licensing / batchmode 问题

现象：Unity 退出码异常，日志出现 LicensingClient。

处理：加 `-InteractiveEditor`。

### 8.4 客户端加入失败

现象：`join-failed:*`

处理：看 `server.err.log`，确认 server 启动成功且客户端能连上 `20101`。

### 8.5 球体位置看起来不对

现象：球埋进地面，或悬空。

原因：`ToWorldPosition` 的 Y 与 `localScale` 不匹配。

处理：确认 `BallVisualRadius = 0.45f`，`localScale = one * (BallVisualRadius * 2)`，
且 `ToWorldPosition` 的 Y 用的是 `BallVisualRadius`。三者必须一致。
